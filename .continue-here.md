Current task status:

- class management grade taxonomy is now expanded and unified in code:
  - preschool: `小班 / 中班 / 大班`
  - school age: `一年级 ~ 六年级`
  - post-school age: `七年级（初一）~ 九年级（初三）`
  - source of truth: `src/types/class.ts`
- class naming, grade labels, batch class creation, and grade-upgrade logic now use the same grade mapping instead of hard-coded `1-6年级`
- class-management module filter is now aligned to the 6 internal training entries:
  - `感官统合训练`
  - `情绪调节`
  - `社交沟通`
  - `精细动作`
  - `安抚教具`
  - `生活自理`
- academic year is no longer inferred only from existing classes:
  - new independent table: `sys_academic_year`
  - initialization now backfills existing academic years from `sys_class` and `student_class_history`
  - initialization also seeds current academic year plus next academic year when missing
- admin-facing academic-year maintenance is now landed in class management:
  - file: `src/views/admin/ClassManagement.vue`
  - admins can open `学年管理`
  - admins can create academic years before any class exists
  - admins can edit an academic year
- student class assignment now reads academic years from the independent source instead of class-derived year sets:
  - file: `src/views/admin/StudentClassAssignment.vue`
- verification completed this round:
  - `npm run type-check` passes

Problems / blockers / risks:

- no hard blocker in code; type-check passes
- manual runtime verification is still pending
- `sys_academic_year` is a new source of truth:
  - old DBs should auto-backfill on init
  - this still needs real-app verification against the local runtime DB
- editing an existing academic year now rewrites:
  - `sys_class.academic_year`
  - `student_class_history.academic_year`
  - avoid renaming one academic year into another already-existing academic year
- class statistics still aggregate by `module_code`, not by the 6 entry codes:
  - `精细动作` still reuses `sensory` statistics
  - `安抚教具` still reuses `emotional` statistics
  - this was kept intentionally to avoid a larger statistics-view refactor in the same turn
- `src/database/schema/class-schema.sql` has only been partially aligned with the runtime init path:
  - `sys_academic_year` definition is added
  - broader example-data cleanup in that schema file is still not done

Key decisions made in this conversation:

- introduce an independent academic-year table instead of continuing to infer year options from existing classes
  - reason: the user explicitly needs admins to create and edit academic years even when no class exists yet
- keep academic-year format constrained to `YYYY-YYYY`
  - reason: current codebase already assumes academic-year parsing, September start, and August end around that format
- when an academic year is renamed, propagate the new value into class and class-history tables
  - reason: keeping academic-year text inconsistent across `sys_academic_year`, `sys_class`, and `student_class_history` would break filtering and upgrade flows
- keep the class-management module selector aligned to the 6 training entries, but do not refactor statistics storage in the same change
  - reason: the UI/business requirement changed immediately, while statistics currently remain compatible only at `module_code` granularity
