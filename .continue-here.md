Key decisions made in this conversation:

- switch backup coverage from a hard-coded table whitelist to live sqlite table discovery
  - reason: the old whitelist had fallen behind current schema and directly caused missing class, plan, report, and training data after restore
- keep explicit exclusions only for transient migration tables
  - reason: the safer default for this repo is “cover current live user tables unless explicitly excluded,” not “remember to manually add every new table forever”
- make overwrite restore clear target tables before replaying records
  - reason: the previous implementation skipped empty backed-up tables, which left stale live data behind during overwrite restores
- disable foreign-key checks during replay, then validate afterward
  - reason: full-schema restore should not depend on perfect insert ordering across dozens of related tables, but it still must fail if the final restored state is inconsistent
- recalculate class-derived state after restore
  - reason: class-management triggers and snapshot fields can drift during raw replay, so restore needs an explicit reconciliation step instead of assuming inserts preserve derived values automatically
- align class-management shell layering with student-management
  - reason: the previous class-management page looked like it had a different page background because filter, stats, and list content were wrapped in one extra outer white panel
- keep the pill hover animation, but fix clipping by adding container safe padding instead of removing the motion
  - reason: the hover lift is still useful feedback; the bug was the scroll container clipping the outline, not the animation itself
- remove the redundant breadcrumb copy from the three entry-selection pages
  - reason: the pages already have clear H1 titles and subtitles, so `游戏训练 / 选择入口` style helper text added noise without improving orientation
