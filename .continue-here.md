## 2026-03-26 Entry Unification Planning Checkpoint

### What changed in this checkpoint

- No runtime route/page/database behavior was changed yet.
- Added a new shared helper:
  - `src/utils/training-entry.ts`
- Refactored the old equipment-only helper into a thin compatibility wrapper:
  - `src/utils/equipment-training-entry.ts`

### Why this checkpoint exists

The next planned refactor is larger than a safe mid-session patch:

- `游戏训练`
- `器材训练`
- `训练记录`

all need to converge on the same 6 internal training entries:

- `sensory-integration`
- `emotional-regulation`
- `social-communication`
- `fine-motor`
- `soothing-aids`
- `life-skills`

The user explicitly decided:

- no old-record compatibility
- old training/game/equipment records can be physically deleted
- do not carry legacy baggage forward

Before touching routes and DB writes, a shared `training-entry` helper was created so the next session can refactor all three chains around one source of truth instead of continuing to fork the model.

### Confirmed technical conclusions

1. Training records cannot be truly split into 6 entries unless record persistence gains `entry_code`.
2. Updating only the training-record menu would create fake grouping, because current game/equipment records are still grouped only by top-level `module_code`.
3. Game training also has to move to the same entry model.
4. `emotional-regulation` and `soothing-aids` cannot keep sharing plain top-level `emotional` routing logic, or they will leak each other's game space.
5. Because old records are explicitly disposable, the correct implementation path is a hard cut, not a compatibility layer.

### Next session implementation target

Implement the full hard-cut entry unification:

1. Extend DB schema and write paths:
   - add `entry_code` to `training_records`
   - add `entry_code` to `equipment_training_records`
   - add any required emotional game/session linkage fields
2. Physically clear old training/game/equipment record data during the migration cutover.
3. Refactor `游戏训练` to use `entry` instead of only `module`.
4. Refactor `训练记录` menu/detail pages to use the same 6-entry UI model as `器材训练`.
5. Keep top-level authorization mapped to real business `moduleCode`, not promoted entry codes.
