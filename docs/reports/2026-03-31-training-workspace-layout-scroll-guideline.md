# 训练工作台双栏滚动布局规范

日期：2026-03-31

适用页面：

- `src/views/equipment/QuickEntry.vue`
- `src/views/games/GameLobby.vue`
- 后续所有“左侧资源列表 + 右侧录入/预览”页面

## 1. 问题定义

这类页面如果直接依赖外层路由容器滚动，会出现两个典型问题：

1. 左侧列表条目很多时，鼠标滚轮会把整个页面一起向下推。
2. 右侧录入区或预览区会被滚出视口，导致用户一边找资源、一边丢失当前操作上下文。

这不是业务问题，而是滚动归属错误。

## 2. 当前规范

双栏工作台页面统一遵守以下规则：

1. 页面根节点不负责纵向滚动。
2. 左右栏各自成为独立滚动容器。
3. 左栏用于长列表滚动，右栏用于录入表单或预览卡片的可视区保持。
4. 栏内滚动不得继续冒泡到外层路由容器。

## 3. 统一实现方式

当前公共样式已落在：

- `src/assets/layout.css`

统一使用以下类名：

- `workspace-page`
  - 页面根容器占满当前路由内容区
  - `height: 100%`
  - `min-height: 0`
  - `overflow: hidden`
- `workspace-split`
  - 双栏主体区域
  - 负责横向分栏和关闭外层滚动
- `workspace-pane`
  - 左右栏独立滚动容器
  - 必须包含 `min-height: 0`
  - 必须包含 `overflow-y: auto`
  - 必须包含 `overscroll-behavior: contain`
- `workspace-pane-card`
  - 右栏内部顶对齐卡片
  - 让卡片按内容高度显示，不强制拉伸

## 4. 为什么不用固定定位

不推荐把右侧录入区直接做成 `position: fixed`：

- 固定定位会脱离当前页面布局流，容易和主布局、响应式宽度、弹窗层级产生新冲突。
- 页面头部、面包屑、不同模块顶部高度不完全一致，固定定位通常会引入更多补偿逻辑。
- 当前问题的根因不是“右侧不够固定”，而是“外层容器不该滚”。

优先修正滚动归属，比增加额外定位层更稳。

## 5. 实施结果

本次已落地到：

- `src/views/equipment/QuickEntry.vue`
- `src/views/games/GameLobby.vue`

实现后，预期行为是：

- 左侧器材/游戏列表滚动时，外层路由内容区不再跟着滚动。
- 右侧录入区/预览区默认保持在当前视口内。
- 当右侧内容未来增长时，仅右栏自身滚动，不影响左栏定位。

## 6. 后续新增页面检查项

新增类似工作台页面时，提交前至少确认：

1. 根节点是否使用 `workspace-page`
2. 主体区域是否使用 `workspace-split`
3. 左右栏是否都使用 `workspace-pane`
4. 是否补上了 `min-height: 0`
5. 是否避免重新把滚动放回外层 `.content` 或页面根容器
