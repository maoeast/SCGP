# SCGP 用户手册 · 截图采集与维护基线（内部文档）

> 职责：承载对外版《用户使用手册》不收录的内部生产资料——截图清单（211 张）、采集验收标准、文档维护基线。
> 何时读：补拍/新增手册截图、修改手册结构、新增量表或功能需要同步手册时。
> 关联：对外手册 `SCGP-星愿能力发展平台用户使用手册.md`；截图管线 `scripts/manual/`（plan → scenarios → capture → approvals → promote → generate → validate）。
> 本文件由对外手册第 18 章拆出（2026-09-10），此后截图清单只在这里维护，不再进 Word。

## 1. 文档维护基线

对外手册编写时主要核对了生产路由、侧边导航、角色元数据、评估量表目录、训练入口目录、资源中心、AI 智能体、系统管理和当前有效上下文。后续功能变化时，应优先重新核对当前代码，再更新手册 Markdown 并重新生成 Word；不要从历史《系统使用说明书》直接复制未验证内容。

截图计划的唯一事实来源为 `scripts/manual/user-manual-screenshot-plan.mjs`（211 行，行序即编号序）。正文新增、删除或调整截图占位后，应先运行 `node scripts/manual/sync-user-manual-screenshot-plan.mjs` 同步编号，再生成 Word。

生成链固定顺序：sync → `node scripts/manual/generate-user-manual.mjs --include-approved-screenshots`（docx，gitignore 不入库）→ `node scripts/manual/validate-user-manual.mjs`（mammoth 抽 docx 文本断言）。

## 2. 截图采集验收标准

- 使用统一窗口尺寸（1920×1080，DPR 1）和同一套脱敏演示数据。
- 每个编号只对应一个可复现界面状态；跨页面、弹窗、互斥图层以及操作前后结果必须拆分编号。
- 文件名统一为 `Sxxx.png`，正文占位、plan 行和图片文件一一对应（对外版 Word 不再包含清单表）。
- 同一张图片不得重复用于多个编号；正文引用已有截图时只引用原编号。
- 不出现真实 API Key、激活码、机器码、电话或学生敏感信息。
- 不截开发者调试页、迁移工具页或浏览器模拟错误页。
- 弹窗截图必须包含完整标题、主要字段和操作按钮。
- 表格截图保留列名和至少两条有代表性的脱敏数据。
- 删除、恢复、更新、迁移、清理等高风险状态，只能在可丢弃的演示数据库、临时资源或受控模拟状态中采集。
- 原生系统提示、Toast 和更新状态采用对应的专项采集方法；不得为截图执行真实重启、安装或覆盖正式数据。
- 采集完成后经人工审批写入 `docs/user-manual/screenshot-approvals.json`，再由 `promote-user-manual-screenshots.mjs` 校验 SHA-256 后落 `docs/user-manual/screenshots/`；正文占位编号保持不变。
