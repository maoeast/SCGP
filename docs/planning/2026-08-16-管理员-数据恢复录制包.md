# 《管理员：数据恢复》人工录制包

> **状态**：当前有效，待按本包录制与验收
> **产品**：SCGP / 星愿能力发展平台
> **受众**：首次使用系统的学校管理员
> **成片目标**：2–3 分钟、16:9；先无声录屏，再配 AI 旁白和字幕
> **范围**：用备份文件执行一次完整数据恢复（读取备份信息 → 确认覆盖 → 恢复），并回查被删除的演示数据已恢复
> **系列**：本片为第十七支，承接《管理员：数据备份》（第十三支演示备份，本片演示恢复）；业务数据已就绪。
> **不作为事实来源**：`output/videos/管理员：班级与学生管理.mp4`、`scripts/video/` 及其旧分镜仅为历史参考，不能复用其时长、分辨率、样例数据、旁白、选择器或语音配置。

## 1. 本片要解决什么

本片演示管理员在“系统管理 → 数据备份”中用备份文件执行完整数据恢复：选择备份文件并输入口令读取备份信息，确认覆盖后执行恢复，并回查恢复前被删除的演示数据已完整回来。

数据恢复用备份文件覆盖当前数据库，可恢复班级、学生、计划、报告与训练记录等全部业务数据。本片只在可丢弃录制库上演示恢复，不涉及任何生产数据。本片只说明这一业务结果，不承诺替代学校既有的容灾或归档制度。

### 角色与范围边界

- 录制账户为**管理员**，旁白以“管理员”指代操作者（系统管理仅管理员可进入）；不得把操作表述为教师、学生或其他角色。账号信息不出现在画面中。
- 演示页面：系统管理 → 数据备份页签（选择备份文件、备份文件信息、恢复数据）与学生管理列表（恢复前后回查）。
- 录制库为可丢弃环境：录制前已创建备份并删除一名演示学生（删除过程不拍摄，仅作为恢复前状态）。
- 不演示：备份流程（已由第十三支覆盖）、备份口令不一致、恢复失败的错误画面、资源健康检查细节、其他系统页签。
- 不演示导入、数据库替换、数据抽取、演示 ZIP 修改或产品数据目录写入。`docs/guides/seed-demo-data.md` 仅可作为历史参考，不是本片的执行路径。

## 2. 录制前置条件与安全检查

在打开录制软件前，由执行人逐项确认。任一项不满足时，停止录制并先修正环境，不用剪辑掩盖问题。

| 检查项 | 必须满足的条件 |
| --- | --- |
| 账户与页面 | 已使用管理员账户登录；左侧菜单“系统管理”“学生管理”可见可进入。 |
| 数据环境 | 使用可丢弃、可完整恢复的录制数据库；绝不连接生产库或含真实人员信息的库。 |
| 预检备份 | 录制前已在同一录制库中执行一次备份（口令 `[备份口令]`，与第十三支一致的流程），备份文件保留在固定位置供录制时选择。 |
| 预删数据 | 录制前在录制库中删除一名演示学生 `[被删除的演示学生]`（删除过程不拍摄；可通过既有维护手段完成），使其在恢复前不在学生列表中；录制库中保留另一名虚构学生 `[虚构学生姓名]` 供回查对照。 |
| 文件位置 | 备份文件选择对话框出现后直接选择预检备份文件，画面不得聚焦展示完整文件路径（必要时跳剪）。 |
| 运行状态 | 页面加载完成、无报错提示、浏览器/系统通知关闭，缩放和字体在 16:9 画面中清楚可读。 |
| 回滚 | 已明确录制结束后的恢复方式：还原该可丢弃数据库或按既有安全流程清理；删除备份文件；不得对真实库做清理。 |

运行时只使用以下占位符替换为已核验的实际值：

- `[备份口令]`（录制用虚构口令）
- `[被删除的演示学生]`（录制前预删，恢复后回查）
- `[虚构学生姓名]`（留存的对照学生）

### 2.1 录制效率提示

- **批次**：F-4（依赖第 13 支的备份流程做预检）。
- **预置**：预检先备份并删除一名演示学生（删除过程不拍摄）。
- **一次通过要点**：①预删学生必须在录制前完成；②"恢复数据"有覆盖确认框；③回查以预删学生回来为业务证据，务必拍到列表对比。
- **净录制预估**：约 25 分钟/遍。


## 3. 画面、操作与后期总规则

### 3.1 画面规格

- 成片画布为 **16:9**，建议交付 `1920 × 1080`；若源窗口比例不同，应在录制前调整可见区域或后期裁切，不能拉伸界面。
- 录制原始画面时关闭系统声音、应用提示音和通知；录屏只保留清晰的界面操作，AI 旁白在后期单独合成。
- 每个镜头只表达一个意图。页面、下拉菜单和对话框完全稳定后再开始操作；不录入加载抖动、无关菜单或鼠标试探。
- 需要突出字段时仅做克制的局部放大，放大前后保留页面方向感；不使用快速摇镜、夸张缩放或遮挡主要操作区的特效。

### 3.2 鼠标与停留规则

- 鼠标沿短路径移动，点击后离开关键文字；不要绕圈、反复悬停或用光标代替旁白。
- 打开页面、文件选择对话框或确认框后停留约 **1 秒**，让观看者看清标题和内容。
- 口令输入为密码框，输入后不悬停暴露明文；文件选择对话框不聚焦路径。
- 成功提示“数据恢复成功。…”保留 **0.8–1.5 秒**；恢复完成后停留至回查完成。
- 出现任何可见错误、重复校验、错误数据、误点击或个人信息时，**从该镜头开头重录**；不要以裁切、马赛克或加速掩盖操作错误。

### 3.3 旁白与字幕规则

- 旁白使用经试听通过的中文 AI 声音；本包不指定具体供应商、声音名称或固定语速。
- 旁白应说明“为什么做”和“操作结果”，不逐字念出每次鼠标点击；画面中的按钮和字段由字幕辅助定位。
- 字幕与旁白同义、逐镜头校时。每条最多两行，避免遮挡口令对话框、确认框、按钮、备份文件信息区及成功提示。
- 术语以实时构建为准：如录制构建调整了文案，可替换字幕中的对应词，但不得改变“读取信息 → 确认覆盖 → 执行恢复 → 回查”的业务顺序。

## 5. 录制执行清单

1. 按第 2 节完成可恢复环境检查：确认预检备份存在、预删学生完成、口令一致；记录全部运行时占位符的实际值。
2. 先静音录一遍完整画面；仅检查流程、隐私、光标和停留，不在此阶段生成旁白。
3. 回看原始录屏：任何数据泄露、加载异常、错误提示、误点“立即备份”、口令输入错误、文件路径进入画面、覆盖确认未展示或恢复后未能回查，都从受影响镜头开头重录。
4. 依据第 4 节生成 AI 旁白，先输出可试听音频，再与已确认的画面匹配；不要直接把未经试听的 TTS 音频导出为成片。
5. 依据字幕列制作字幕，逐句检查进入和离开时间；字幕出现应略早于或与对应动作同时，不应滞后到下一步。
6. 完成合成后，从头无中断观看一次；验收通过才导出交付版。录制结束后立即按预先确认的可恢复流程恢复环境并删除备份文件。

## 6. 音频、剪辑与导出门禁

### 6.1 音频试听门禁

在最终合成前，至少由录制者完整试听一次 AI 旁白，并逐项通过：

- 声音自然、适合面向学校管理员的说明语气；
- 语速能让观看者同时看清口令流程、确认框和操作，关键停顿自然；
- 音量在全片一致，未被系统声、背景音乐或提示音覆盖；
- “数据恢复”“选择备份文件”“备份口令”“备份文件信息”“恢复数据”“覆盖当前所有数据”“数据恢复成功”等中文术语发音正确；
- 无漏读、重读、截断、机械连读或难以辨识的词句。

任一项不通过时，只重生成或重校该段音频并复听；不要通过过度加速、压缩静音或堆叠背景音乐掩盖问题。

### 6.2 画面与字幕门禁

- 每个镜头都可独立看懂一个意图，转场不打断一次读取、确认、恢复或回查动作。
- 关键页面标题、按钮“选择备份文件”“恢复数据”、口令对话框、覆盖确认框、备份文件信息区和最终回查列表在 16:9 画面中可读。
- 字幕不遮挡口令对话框、确认框、按钮、备份文件信息区或成功提示；无错别字、占位符、旧产品名称或历史样例数据。
- 成片不得出现真实个人数据、管理员账号、令牌、**文件路径（含文件选择对话框的完整路径）**、通知横幅、调试窗、密码管理器或录制工具控件。
- 导出为可播放的 16:9 MP4（H.264 视频与 AAC 音频为推荐兼容组合）；导出后使用独立播放器从头试听、查看字幕和核验总时长。

## 8. 当前实现依据与维护说明

本录制包依据当前界面和数据行为编写：

- `src/views/System.vue`：系统管理容器与“数据备份”页签（选择备份文件、备份文件信息、覆盖确认与恢复流程、“数据恢复成功”提示）；
- `src/database/backup-manager.ts`（或等价备份模块）：`loadBackupFromFile`/`getBackupInfo`/`importData`（覆盖恢复）；
- `src/views/Students.vue`：学生管理列表（恢复前后回查）；
- `src/router/index.ts`：`/system`、`/students` 路由（仅 admin 进入系统管理）。

界面文案或业务规则变动时，先以当前代码和实际构建复核，再同步更新本包；不要反向用本包覆盖当前产品事实。
