# 首页看板「智能特教助理」：评估缺口与干预建议（口径与实现）

> 状态：已实现（2026-09-21）。本文是该面板**分析口径的唯一真源**：数据来源、信号定义、优先级规则、阈值取舍与不做什么。
> 涉及代码：`src/services/assessment-gap-analysis.ts`（纯函数）、`src/database/dashboard-api.ts#getAssessmentInsights`、`src/views/Dashboard.vue`。

## 1. 为什么有这份文档

面板原实现（`dashboard-api.ts` 2026-03-19 版）只有一条 SQL 阈值：最近一次评估早于 6 个月 → 提醒复测；文案却写「根据真实评估缺口提供优先干预建议」。2026-09-21 排查确认两个缺陷：

1. **覆盖缺口**：UNION 只列 8 张量表主表（sm/weefim/csirs/conners_psq/conners_trs/sdq/srs2/cbcl），而 catalog 已有 18 个量表；此后新增的 ABC/ATEC/PEP-3 等 10 个量表从未同步。真库实测：只在 ABC/ATEC/CRT/认知自我建过基线的学生被判「尚无评估记录」。
2. **名不副实**：不读任何分数/维度/领域，只有两条固定模板句。

本次把面板做实，并把口径沉淀到本文。

## 2. 数据来源（单一真源）

| 环节 | 真源 | 说明 |
|---|---|---|
| 量表主表清单 | `assessment-quality-api.ts` 的 `QUALITY_TABLES`（18 项） | 与 catalog（`assessment-scale-catalog.ts`）双向守卫（见 §6） |
| 每生每量表「最新一行」 | `DashboardAPI.getAssessmentInsights` 逐表 `GROUP BY student_id` + `MAX(created_at)` | 18 条查询；表名由 `QUALITY_TABLES` 拼装，**禁止硬编码** |
| 等级 / 分数归一化 | `SCORE_ADAPTERS[code].normalizeRow(row)` | 与 AI 纵向趋势（`get_assessment_trend`）同一条归一化路径，杜绝两处口径漂移 |
| 领域映射与强弱判定 | `assessment-profile.ts`：`SCALE_DOMAIN_MAP` / `DOMAIN_LABELS` / `strengthFromLevel` / `aggregateStrengthFromLevels` | 与跨量表画像（雷达图）同源 |
| 教师数据隔离 | `getCurrentTeacherStudentScope('s')` | 教师仅见任教班级学生；admin 全量 |

适配器键口径：catalog 用连字符（`conners-psq`），适配器与领域映射用下划线（`conners_psq`），转换规则 `code.replace(/-/g, '_')`。

## 3. 四类信号

1. **明显偏弱（danger）**：某发展领域内某量表最近一次等级命中危险词（`极重度/重度/严重/明显落后/异常/临床/迟缓/severe/extreme/abnormal/clinical/delayed/verylow`）→ 建议「优先安排干预」。
   - 危险词**单独命中即判定**，不依赖聚合强弱门：个别危险词（如 `extreme` / `verylow`）不在 `strengthFromLevel` 的负向词表里，若放在聚合门之后会漏报（`resolveDomainSeverity` 先查危险词再查聚合）。
2. **偏弱需关注（warning）**：该领域判定为弱但未命中危险词（典型：`轻度/中度/边缘/偏低/borderline/mild/moderate`）→ 建议「结合其他量表交叉验证后安排训练」。
   - 溯源规则（与判定同源，`resolveDomainSeverity`）：建议句引用的量表名 + 日期 + 等级，必须是**触发该判定的那条等级**（danger 取最近的命中危险词的快照；warning 取最近的判为弱的快照）。不得引用该域内只是日期更新的量表——否则会出现「明显偏弱（某量表 · 等级「正常」）」这种自相矛盾的引用。
3. **评估缺口**：该学生从未测过的 5 大发展领域（感觉统合 / 情绪调节 / 社交沟通 / 认知发展 / 生活自理）；**缺 ≥3 个领域**才单独构成待办（`MIN_MISSING_DOMAINS_FOR_BASELINE_INSIGHT`）。
4. **从未评估 / 超期未复评**：全量表库无记录；或最近一次评估早于 6 个月（`DEFAULT_OVERDUE_MONTHS`，与旧口径一致）。

**只计覆盖、不下强弱结论的量表**（`COVERAGE_ONLY_SCALE_CODES`）：`crt`、`cognitive_self`（实验性占位常模，与 `UNSUPPORTED_SCALE_CODES` 同一决策）、`cpep_3`（等级字段是「总发展当量 N 月」，无强弱语义）。三者都计入「最近评估时间」；领域覆盖另论——`cpep_3` 在 `SCALE_DOMAIN_MAP` 里有映射（社交沟通），因此同时计入该领域覆盖；`crt` / `cognitive_self` 无领域映射，**不覆盖任何领域**（只做过这两张量表的学生会被判为 5 大领域全缺——属实：确实没有任何发展领域的评估记录）。

## 4. 优先级与排序

优先级分（越大越前）：

```
明显偏弱        +1000   （任一领域 danger）
从未评估        + 500
偏弱需关注      + 300   （无 danger 但有 warning）
评估缺口        + 10/领域（上限 5 个）
超期未复评      +   5
```

其次是「最近评估更久者优先」，再是「新建档优先」，最后按学生 id 稳定兜底。

**为什么分 danger/warning**：特教群体里「轻度/中度/边缘」是常态。真库实测：不分级时 43/43 名学生全部命中「偏弱或缺口」，面板退化成全员名册；分级后前 4 条稳定落在 11 名明显偏弱学生上，其余 32 名排在后面的「查看全部」列表里。

**为什么缺口要阈值**：5 大领域任意一个未测都算缺口。真库实测：缺 ≥1 个领域者为 40/43，缺 ≥3 个为 23/43，缺 ≥4 个仅 1/43。取 3（覆盖不足半数领域）是「基线明显不完整」与「不淹没真正的优先级」之间的折中；未达阈值的缺口仍出现在该学生的标签与建议句里（如果他因其他信号入列）。

## 5. 面板行为

- 面板显示前 4 条（与「本周异常预警」「今日训练日程」的截断一致）；角标为 **「优先 N · 共 M」**——优先 = 明显偏弱或尚无评估记录（`isPriorityInsight`），无优先项时退回「M 条」；超 4 条时出现「查看全部」→ 弹窗按优先级列全量。
- 指标卡「待评估提醒」数字 = 待办总数（口径不变）；hero 文案带「（其中 N 条需优先处理）」。为何拆：特教学生基数大，待办总数常常接近学生总数（真库 43/43），单看总数信息量低。
- 条目可点击 → `/students/{id}`（学生详情，评估与训练记录）；支持键盘 Enter/Space。
- 已覆盖但无任何信号的学生**不出现在清单里**——面板是待办清单，不是花名册。

## 6. 守卫与验证

- `scripts/tests/dashboard-assessment-coverage.test.mjs`（`test:core:node`）：① 覆盖 catalog 全部 18 量表 ② 表清单必须由 `QUALITY_TABLES` 派生、dashboard-api 不得出现裸表名 ③ 每个量表要么注册适配器、要么显式声明仅计覆盖（新增量表不得静默漏判）④ 表名白名单。
- `tests/assessment-gap-analysis.test.ts`（`test:core:ts`）：9 组断言覆盖四类信号、cpep_3 仅计覆盖、同域多量表时的溯源归属、危险词单独命中、优先级次序、无信号学生不入列。
- 真库只读复算（2026-09-21）：43 名学生 → 43 条待办（明显偏弱 11 / 偏弱需关注 32）；学生 1 由误报变为「社交沟通 明显偏弱 + 4 个领域未评估」。

## 7. 明确不做（与原因）

- **不给器材推荐 / 一键生成计划**：推荐引擎（`features/recommendation`）依赖 `DimensionScore.severity`，而 severity 不入库（评分时在 Driver 内实时计算，`init.ts` 全库无 severity 列），无法从历史数据复现。要做需先把 severity 落库。
- **不接 LLM**：面板必须在未配置模型服务时照常工作；AI 深度解读走「AI 助手」入口（`ai-agent-presets`）。
- **不下医学结论**：全部结论都引用真实量表名 + 日期 + 等级原文，措辞限于「建议补测 / 交叉验证 / 优先安排干预」。
- **不改变既有 6 个月口径**：超期阈值仍为 6 个月，只降级为四类信号之一。
