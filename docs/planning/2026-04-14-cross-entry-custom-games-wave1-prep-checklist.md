# 跨训练入口自定义小游戏 Wave 1 前期准备清单

> 文档类型：执行前准备清单
> 状态：当前有效
> 最后更新：2026-04-15

## 1. 目的

本文件用于指导下一轮会话在 **不重做 `Phase 0`、不直接铺开 `Wave 1` 全量实现** 的前提下，先完成 `Wave 1` 的最小前期准备。

当前代码现实必须先说清：

- `Phase 0` 已完成收口与手动验证
- 当前真实运行链路仍是 `emotional-only`
- `Wave 1` 还没有开始正式实现

## 2. 本轮前期准备只做什么

下一轮会话只做以下 6 件事：

1. 锁定 `Wave 1` 的单一最小目标
2. 补齐该目标的最小定义
3. 核对现有底座是否足够承载
4. 判断是直接复用底座，还是只补一个最小底座缺口
5. 输出最小验收清单
6. 标注既有非本轮阻塞

## 3. 约束

- 不重做 `Phase 0` 规划
- 不把“跨训练入口目标态”写成当前现状
- 不在本轮同时启动多个 `Wave 1` 目标
- 不直接进入完整业务实现
- 以当前代码为准
- 新游戏默认按 `27` 寸触摸大屏、横向优先布局制作；移动端只做兼容兜底
- 进入游戏后默认使用全屏沉浸式壳；若某个游戏保留平台导航，必须先说明原因

## 4. 最小执行步骤

### Step 1. 锁定 `Wave 1` 单一目标

必须先只选一个：

- 新增 1 个游戏
或
- 将 1 个已存在游戏扩到 1 条新训练入口

需要明确：

- `gameCode`
- 页面路由
- 所属模块
- 所属训练入口
- 是否单人 / 双人
- 是否需要媒体权限
- 是否沿用“横向优先、27 寸触摸大屏”默认布局基线；若不沿用，必须先说明原因

### Step 2. 补齐目标定义

对选中的目标，最少补齐以下定义：

- `gameCode`
- `entryPath`
- `moduleCode`
- `trainingEntryCode`
- `requiredPermissions`
- `maxPlayers`
- 返回页应回哪里
- 完成态如何写记录
- 中断态如何写记录
- 是否需要徽章

输出形式可以是：

- 更新现有 planning 文档
或
- 新增一个仅针对该目标的短 planning 文档

### Step 3. 核对现有底座

必须回到当前代码核对以下 3 处：

- `src/data/custom-game-registry.ts`
- `src/utils/custom-game-launch.ts`
- `src/views/emotional/games/GameContainer.vue`

核对问题只回答这些：

- 新入口参数能否稳定转成 `launchContext`
- 返回路径是否已能表达
- 权限模型是否已足够
- 单人 / 双人上下文是否已足够
- 持久化字段是否已足够

### Step 4. 给出底座结论

结论只能是两种之一：

- 现有底座足够，`Wave 1` 可直接开始业务实现
- 只差 1 个最小底座缺口，先补这个缺口再进业务实现

不允许在这一步扩散成新的平台级重构清单。

### Step 5. 固定验收清单

进入 `Wave 1` 真正实现前，先固定最小验收标准。

至少包括：

- 能进入目标游戏
- 权限链路正常
- 完成记录正常写入
- 中断退出正常写入
- 返回入口正常
- 旧库不因 schema 差异报错
- 不引入新的主进程异常弹窗
- 页面内不出现面向程序员的实现文案，例如状态码、字段名、事件名或调试语汇
- 沉浸式页面完整铺满可视区，不露出 `Layout` 黑底、底部黑边或未接管背景的外层容器

如果目标涉及摄像头或麦克风，额外必须包含：

- `blocked_system` 恢复页验证
- 打开系统设置
- 返回后重新检测恢复

### Step 6. 标注既有非本轮阻塞

下一轮会话必须明确写清：

- `type-check:emotional` 仍受仓库既有 TS7016 阻塞
- `src/config/CNBSR2016FeedbackConfig.js`
- `crypto-js` 类型缺失

这两项默认不算 `Wave 1` 新回归。

## 5. 推荐输出格式

如果下一轮会话完成本清单，建议输出结果至少包含：

- 当前代码现实
- 选中的 `Wave 1` 单一目标
- 底座是否足够
- 如果不够，还差哪一个最小缺口
- 最小验收清单
- 是否可以进入 `Wave 1` 实现
