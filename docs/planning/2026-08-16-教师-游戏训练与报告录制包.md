# 《教师：游戏训练与报告》人工录制包

> **状态**：当前有效，待按本包录制与验收
> **产品**：SCGP / 星愿能力发展平台
> **受众**：首次使用系统的学校教师（管理员可代为录制）
> **成片目标**：2–3 分钟、16:9；先无声录屏，再配 AI 旁白和字幕
> **范围**：从游戏训练入口组选择学生，在游戏大厅开始一次感官游戏（颜色配对），完成后自动生成并查看 IEP 评估报告
> **系列**：本片为第七支，承接《教师：器材训练与记录》（第六支为器材链路，本片为游戏链路，共用训练记录主链）；学生档案与班级已就绪。
> **不作为事实来源**：`output/videos/管理员：班级与学生管理.mp4`、`scripts/video/` 及其旧分镜仅为历史参考，不能复用其时长、分辨率、样例数据、旁白、选择器或语音配置。

## 1. 本片要解决什么

本片演示教师如何通过“游戏训练”完成一次感官游戏训练并查看报告：选择训练入口组与学生，在游戏大厅选定游戏与参数，进入全屏训练逐轮作答，训练完成后系统自动生成 IEP 评估报告。

游戏训练是训练记录主链（`training_records` + `training_session` 统一主表）的入口之一，完成时同步生成 `report_record`（IEP 报告）供教师查看训练数据与建议。本片固定演示**颜色配对**（视觉配对类，无需摄像头，适合录屏演示）；本片只说明这一业务结果，不承诺替代学校既有的训练、评估或档案流程。

### 角色与范围边界

- 录制账户为**教师或管理员**，旁白以“教师”指代操作者（游戏训练对教师开放）；不得把操作表述为学生、家长或其他角色。账号信息不出现在画面中。
- 演示页面依次为：游戏训练 → 训练入口组卡片 → 选择学生 → 游戏大厅（预览与参数配置）→ 全屏训练（轮次作答）→ IEP 评估报告。
- 仅使用一名虚构学生与产品演示数据中的游戏；不展示真实姓名、学号、照片、诊断、联系方式或真实训练记录。
- 不演示：依赖摄像头的游戏（如空气木琴、打泡泡等手部追踪类）、情绪入口小游戏、中途“返回准备页”退出、报告页导出 PDF/Word、训练记录菜单回查。
- 不演示导入、数据库替换、数据抽取、演示 ZIP 修改或产品数据目录写入。`docs/guides/seed-demo-data.md` 仅可作为历史参考，不是本片的执行路径。

## 2. 录制前置条件与安全检查

在打开录制软件前，由执行人逐项确认。任一项不满足时，停止录制并先修正环境，不用剪辑掩盖问题。

| 检查项 | 必须满足的条件 |
| --- | --- |
| 账户与页面 | 已使用教师或管理员账户登录；左侧菜单“游戏训练”可见可进入。 |
| 数据环境 | 使用可丢弃、可完整恢复的录制数据库；游戏资源（`sys_training_resource`，resource_type=game）已就绪；绝不连接生产库或含真实人员信息的库。 |
| 虚构学生 | 一名虚构学生 `[虚构学生姓名]` 已建档，且对录制账户可见（教师账户受数据范围限制时，改用管理员账户录制）。 |
| 游戏资源 | `[对应的训练入口]`（推荐“感官统合训练”）下存在 `[已选定的游戏]`（推荐“颜色配对”，视觉配对类）；入口卡片计数可见；对应能力包已激活。 |

| 回滚 | 已明确录制结束后的恢复方式：还原该可丢弃数据库（含本次训练记录与 IEP 报告）或按既有安全流程清理；不得对真实库做清理。 |

运行时只使用以下占位符替换为已核验的实际值，不在脚本中预设具体学生名、入口或游戏：

- `[对应的训练入口]`（推荐“感官统合训练”）
- `[虚构学生姓名]`
- `[已选定的游戏]`（推荐“颜色配对”）

### 2.1 录制效率提示

- **批次**：C-3（独立于 5/6，仅需学生；可与批次 C 同库）。
- **预置**：选择"颜色配对"（视觉类、无需摄像头）；入口游戏计数可见。
- **一次通过要点**：①必须选无摄像头游戏（空气木琴/打泡泡排除，隐私+硬件依赖）；②答对约 2.5 秒自动下一轮，勿抢点；③完成后约 1 秒自动跳 IEP 报告。
- **净录制预估**：约 35 分钟/遍（含 5 轮作答）。


## 3. 画面、操作与后期总规则

### 3.1 画面规格

- 成片画布为 **16:9**，建议交付 `1920 × 1080`；若源窗口比例不同，应在录制前调整可见区域或后期裁切，不能拉伸界面。
- 录制原始画面时关闭系统声音、应用提示音和通知；录屏只保留清晰的界面操作，AI 旁白在后期单独合成。
- 每个镜头只表达一个意图。页面、下拉菜单和对话框完全稳定后再开始操作；不录入加载抖动、无关菜单或鼠标试探。
- 需要突出字段时仅做克制的局部放大，放大前后保留页面方向感；不使用快速摇镜、夸张缩放或遮挡主要操作区的特效。

### 3.2 鼠标与停留规则

- 鼠标沿短路径移动，点击后离开关键文字；不要绕圈、反复悬停或用光标代替旁白。
- 打开页面、入口卡片、游戏大厅或配置卡后停留约 **1 秒**，让观看者看清标题和内容。
- 镜头 5 的轮次作答中，答对后约 2.5 秒自动进入下一轮，按此节奏录制，不要抢点；轮次间可用跳剪压缩。
- 训练完成提示“🎉 训练完成！正在生成报告...”保留 **0.8–1.5 秒**（约 1 秒后自动跳转报告页）。
- 出现任何可见错误、重复校验、错误数据、误点击或个人信息时，**从该镜头开头重录**；不要以裁切、马赛克或加速掩盖操作错误。

### 3.3 旁白与字幕规则

- 旁白使用经试听通过的中文 AI 声音；本包不指定具体供应商、声音名称或固定语速。
- 旁白应说明“为什么做”和“操作结果”，不逐字念出每次鼠标点击；画面中的按钮和字段由字幕辅助定位。
- 字幕与旁白同义、逐镜头校时。每条最多两行，避免遮挡游戏卡片、预览配置、轮次进度、作答选项及报告统计卡。
- 术语以实时构建为准：如录制构建调整了文案（含更换入口或游戏），可替换字幕中的对应词，但不得改变“选入口 → 选学生 → 大厅配置 → 全屏训练 → 自动生成报告”的业务顺序。

## 5. 录制执行清单

1. 按第 2 节完成可恢复环境检查，记录全部运行时占位符的实际值。
2. 先静音录一遍完整画面；仅检查流程、隐私、光标和停留，不在此阶段生成旁白。
3. 回看原始录屏：任何数据泄露、加载异常、错误提示、误入摄像头类游戏或情绪小游戏、误点“返回准备页”或“导出 PDF/Word”、或未能自动跳转报告，都从受影响镜头开头重录。
4. 依据第 4 节生成 AI 旁白，先输出可试听音频，再与已确认的画面匹配；不要直接把未经试听的 TTS 音频导出为成片。
5. 依据字幕列制作字幕，逐句检查进入和离开时间；字幕出现应略早于或与对应动作同时，不应滞后到下一步。
6. 完成合成后，从头无中断观看一次；验收通过才导出交付版。录制结束后立即按预先确认的可恢复流程恢复环境。

## 6. 音频、剪辑与导出门禁

### 6.1 音频试听门禁

在最终合成前，至少由录制者完整试听一次 AI 旁白，并逐项通过：

- 声音自然、适合面向学校教师的说明语气；
- 语速能让观看者同时看清游戏界面、轮次进度和操作，关键停顿自然；
- 音量在全片一致，未被系统声、背景音乐或提示音覆盖；
- “游戏训练”“游戏大厅”“进入全屏训练”“训练完成”“正在生成报告”“IEP 评估报告”“训练数据”“准确率”“返回菜单”等中文术语发音正确；
- 无漏读、重读、截断、机械连读或难以辨识的词句。

任一项不通过时，只重生成或重校该段音频并复听；不要通过过度加速、压缩静音或堆叠背景音乐掩盖问题。

### 6.2 画面与字幕门禁

- 每个镜头都可独立看懂一个意图，转场不打断一次选入口、选游戏、作答或报告动作。
- 关键页面标题、入口卡片、游戏预览、轮次进度、作答选项、训练完成提示和报告统计卡在 16:9 画面中可读。
- 字幕不遮挡游戏卡片、预览配置、作答选项、轮次进度或报告统计卡；无错别字、占位符、旧产品名称或历史样例数据。
- 成片不得出现真实个人数据、教师/管理员账号、令牌、文件路径、通知横幅、调试窗、密码管理器或录制工具控件。
- 导出为可播放的 16:9 MP4（H.264 视频与 AAC 音频为推荐兼容组合）；导出后使用独立播放器从头试听、查看字幕和核验总时长。

## 8. 当前实现依据与维护说明

本录制包依据当前界面和数据行为编写：

- `src/views/games/GameModuleMenu.vue`：游戏训练入口组卡片（已激活 tag、游戏计数、授权过滤）；
- `src/views/games/SelectStudent.vue`：选择学生页与进入游戏大厅的跳转；
- `src/views/games/GameLobby.vue`、`src/components/games/GamePreviewCard.vue`：游戏大厅、预览与参数配置、“进入全屏训练”；
- `src/views/games/GamePlay.vue`、`src/components/games/SensoryGameShell.vue`、`src/components/games/visual/GameGrid.vue`：全屏训练、轮次进度与作答反馈（✓ 正确！/ ✕ 再试试看、自动进入下一轮）；
- `src/data/sensory-game-seed.ts`：感官游戏清单（含“颜色配对”）；
- `src/database/api.ts`：`GameTrainingAPI.saveTrainingRecord` 写入 `training_records` 与 `training_session` 统一主表，并生成 `report_record`；
- `src/views/games/IEPReport.vue`：IEP 评估报告（分节评估、总体评估、训练数据统计卡、导出与返回菜单）；
- `src/router/index.ts`：`/games/*` 路由（admin/teacher）。

界面文案或业务规则变动时，先以当前代码和实际构建复核，再同步更新本包；不要反向用本包覆盖当前产品事实。
