# 首页看板「训练进度概览」：数据来源与展示口径

> 状态：已实现（2026-09-21）。本文是该卡片**数据口径的唯一真源**：数据源、窗口与分桶、指标定义、展示与交互、已知取舍、不做什么。
> 涉及代码：`src/database/training-progress-rules.ts`（纯函数与常量）、`src/database/dashboard-api.ts#getTrainingProgress / getTrainingDayDetail`、`src/views/Dashboard.vue`。
> 同一看板的相邻面板口径见 `docs/planning/2026-09-21-首页本周异常预警-判定口径.md`。

## 1. 为什么有这份文档

2026-09-21 用户反馈「这张卡太单薄」，排查发现旧实现（`getWeeklyTrainingTrend`）有四个问题：

1. **数据源是 legacy 表 `training_records`**：器材训练写 `equipment_training_records`、情绪小游戏写 `game_emotion_records`、认知内联游戏只写统一主表——三类都不在旧口径里。真库实测 `training_records` 835 条 / 统一主表 1142 条，**旧口径只覆盖 73.1%**。
2. **同屏两个口径**：旁边「本周异常预警」面板早已切到统一主表 `training_session`，同一屏上两块面板数的不是同一批训练。
3. **空态是死代码**：旧实现的返回数组恒为 7 个点（缺的天补 0），而模板用 `weeklyTrend.length === 0` 判空态——永不成立；零训练的库看到的是一条压在 0 的线，而不是「暂无训练数据」。
4. **卡片只有一条次数线**：接口算出的 `totalDurationMs` 从未渲染；且它不可用（`training_records.duration` 单位混杂：演示脚本写毫秒、自理链写秒，同列 min 480 / max 598000）。

统一训练记录计划 Phase C 已把「首页训练摘要」列为要切到 `training_session` 的消费者（`docs/planning/2026-04-01-unified-training-record-schema-plan.md:200-222`），本次即该闭环。

## 2. 数据源与职责划分

| 环节 | 真源 | 说明 |
|---|---|---|
| 事实源 | **`training_session`**（统一训练主表） | 各训练链双写产物；覆盖 4 类来源：`training_records` 835 / `equipment_training_records` 186 / `game_emotion_records` 101 / `cognitive_game_inline` 20（真库全库，2026-09-21） |
| 时间字段 | `ts.started_at`（会话发生） | **不用 `created_at`**（入库时刻，UTC）：相邻异常面板用本地时间串去比 UTC 的 `created_at`，+08 时区存在约 8 小时窗口偏移（已上报，本轮不复制该写法） |
| 时长 | `ts.duration_ms` | 干净口径；legacy `duration` 单位混杂，不参与任何计算 |
| 完成态 | `ts.completion_status` | 枚举 `completed / cancelled / interrupted / aborted`（建表 CHECK 同源）；完成率分子只认 `completed` |
| 教师隔离 | `getCurrentTeacherStudentScope('s')` | 教师仅见任教班级学生，与看板其它查询一致 |
| 分桶与聚合 | **`training-progress-rules.ts` 的纯函数 `buildTrainingProgress`** | SQL 只取窗口内的原始行，分桶在 JS 侧按**本地日**完成——不用 SQLite 的 `'localtime'` 修饰符（wasm 构建的时区行为不可依赖，且不可单测） |
| 窗口常量 | `TRAINING_PROGRESS_WINDOW_OPTIONS = [7, 30]` / `DEFAULT_TRAINING_PROGRESS_WINDOW_DAYS = 7` | API 与视图均从规则模块取值，禁止内联字面量 |

## 3. 判定口径

**窗口**：最近 **N 个本地自然日（含今天）**，N ∈ {7, 30}，默认 7。区别于「滚动 7×24 小时」——按天出柱时柱子口径干净，最左柱不会是半天。
**环比**：同时取「上一等长窗口」（今天-N … 今天-2N+1）的行做同口径汇总；上一窗口无任何行时 `previous = null`，视图**不显示**环比（不伪造 +0%）。

**时间戳解析**（真库实测两类出处，解析必须都认）：

| 形态 | 出处 | 语义 |
|---|---|---|
| `2026-09-20T10:00:46.836Z`（ISO 带 Z） | 应用实时写入（`new Date().toISOString()`），真库 124 条 | UTC 瞬时，按本地时区换算归日 |
| `2026-09-13 10:00:00`（裸文本） | 演示数据包导入 / 历史回填，真库 1018 条 | 按**本地时刻**理解（种子语义就是「当天 10:00 这类本地课程时间」） |
| 其它 | — | 解析失败计入 `skippedRowCount`，不进聚合、不静默吞 |

**关键指标**（`TrainingProgressSummary`）：

| 指标 | 定义 |
|---|---|
| `sessionCount` | 窗口内会话数（`training_session` 行数） |
| `durationMs` | `SUM(duration_ms)` |
| `studentCount` | `COUNT(DISTINCT student_id)` |
| `completionRate` | `completed / sessionCount`；**无会话时为 `null`**（不猜 0） |
| `activeDayCount` | 窗口内有训练的天数 |
| `todayCount` | **今日**会话数（窗口无关）——日程面板底部进度条的分子与卡片同源 |
| `previous` | 上一等长窗口的同口径指标，用于 KPI 环比 |
| `skippedRowCount` | 时间戳无法解析被跳过的行数（数据质量观测，卡片角落低调提示） |

**模块分布**：按 `module_code` 聚合次数 / 时长 / 学生数，按次数倒序；展示名走 `getTrainingPlanModuleLabel`（与异常面板同一真源），API 层填充，纯函数层不依赖标签工具（保持零别名依赖、可 jiti 直跑单测）。

## 4. 展示与交互

- **头部**：标题 + 窗口分段控件（近 7 天 / 近 30 天，固定枚举走选项控件，不给自由输入）+「查看全部训练记录」（跳 `/training-records/menu`）。
- **KPI 行**：训练次数 / 总时长 / 参与学生（附人均次数）/ 完成率；能算环比时附「较上期 ±X%」（完成率用百分点差值表达）。
- **组合图**：柱 = 每日次数（左轴），折线 = 每日时长分钟（右轴）；tooltip 合并显示「N 次 · 时长」，时长走人读格式（不足 1 小时「N 分钟」，≥ 1 小时「X 小时 Y 分」）——避免长会话显示成「384 分钟」。
- **模块分布**：模块名 + 次数 + 时长 + 按 `share` 宽度的条。
- **钻取**：点某天的柱/点 → `getTrainingDayDetail(date)` → 当日明细弹层（学生 / 模块 / 任务 / 时刻 / 时长 / 完成态），条目点击进学生详情页。**不直跳训练记录页**：该页只认 `entryCode` + `type`，没有日期与学生筛选，跳过去落不到「那一天」。
- **空态**：`hasData === false` → 紧凑空态「暂无训练数据」；KPI 行保留（显示 0 / —），让用户看清窗口口径。
- **响应式**：卡片自身容器查询——≥1100px 左图右分布双栏，<1100px 上下堆叠；不被看板三栏的 520px 固定高度约束（本卡在看板上方，是独立全宽 surface）。

## 5. 已知取舍（真实库只读实测，2026-09-21）

- **覆盖变化**：真库 `training_session` 1142 条 = `training_records` 835 + 器材 186 + 情绪小游戏 101 + **认知内联 20**（后者只存在于统一主表）。旧口径（`training_records`）覆盖 835/1142 = **73.1%**；新口径 100%。
- **窗口数字会变**：真库近 7 个自然日（09-15…09-21）新口径 **1 条会话**（09-20 的一条实时训练）；旧口径滚动 7×24h 是 **9 条**——差额来自演示导入数据的口径差（见下条），不是新口径漏数。近 30 天：**311 条 / 42 名学生 / 完成率 100% / 活跃 15 天**。
- **演示/导入数据的日漂移**：演示种子给同一会话写两个时间——`training_records.timestamp` 是「当日 UTC 零点 + 0–24h 随机毫秒」，`training_session.started_at` 是演示脚本的日期 + 固定时刻（如 `10:00:00`）。随机毫秒会跨本地午夜，于是同一会话在两张表里可能差一天。新口径取统一主表的 `started_at`，与演示数据的**设计意图**一致；旧口径因随机毫秒把部分会话推到了第二天。
- **窗口左边界**：窗口是自然日，今天 0 点之前的会话不再计入——与「今日已完成训练 X 次」的分母（今日计划数）语义一致。
- 真库 `skippedRowCount = 0`（两类时间戳都能解析）。
- 完成率在真库为 100%：写入方默认 `completed`，演示数据没有中断/放弃样本——完成率维度在演示环境看不出差别，属数据侧特征。

## 6. 守卫与验证

- `scripts/tests/training-progress-contract.test.mjs`（`test:core:node`）：① 取数必须以 `training_session` 为主表、不得直扫 legacy 表 ② 必须用 `started_at`、不得出现 `'localtime'` 与 `created_at` 窗口 ③ 窗口/聚合必须来自规则模块（不得内联）④ 视图必须用 `hasData` 判空态、`summary.todayCount` 作进度条分子、注册 `BarChart` ⑤ 文档同步（口径档在册、布局档不再引用已删字段）。
- `tests/training-progress.test.ts`（`test:core:ts`，11 场景）：本地日分桶（跨午夜边界 / ISO-Z 落本地日 / 裸文本按本地时刻）、坏时间戳、窗口外行、时长健壮性、完成率 null、模块排序与 share、汇总去重、环比基准、窗口归一化、时间解析。
- 真库只读复算（2026-09-21）：近 30 天 311 条 / 42 名学生 / 1913 分钟；近 7 天 1 条；`skippedRowCount = 0`。

## 7. 明确不做（与原因）

- **不修异常面板的 `created_at` 口径**：它是独立缺陷（本地串比 UTC 列，+08 疑似 8 小时偏移），本轮只保证新代码不复制该写法；修它要连带重算异常面板的窗口与数字，另开条目。
- **不改演示数据时间轴**：演示训练数据止于 2026-09-13，导致首页卡片在演示环境近 7 天几乎为空。整体按「今天」重锚会牵动评估日期等一批硬编码时间轴，属独立专题；本轮只给截图 fixture 补近 7 天会话（见 §6）。
- **不做趋势异常/基线判定**（如「训练量比该生基线下降 X%」）：需要先定义基线与置信口径，与异常面板的「不做」一致。
- **不动训练记录页的筛选能力**：该页没有日期/学生筛选，本轮以「当日明细弹层 + 查看全部」替代直跳；给记录页加筛选属另一个专题。
- **不修 legacy `training_records.duration` 的单位混杂**：新卡已换源绕开，改历史列是数据迁移专题。
