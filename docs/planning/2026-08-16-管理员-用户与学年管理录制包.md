# 《管理员：用户与学年管理》人工录制包

> **状态**：当前有效，待按本包录制与验收
> **产品**：SCGP / 星愿能力发展平台
> **受众**：首次使用系统的学校管理员
> **成片目标**：2–3 分钟、16:9；先无声录屏，再配 AI 旁白和字幕
> **范围**：在系统管理中创建并维护一个教师账号（新增、编辑、禁用/启用），并在班级管理中新增一个学年
> **系列**：本片为第十一支，承接《管理员：批量分班与学年升级》（第二支使用学年与班级，本片演示学年与账号的维护来源）；学生档案与班级已就绪。
> **不作为事实来源**：`output/videos/管理员：班级与学生管理.mp4`、`scripts/video/` 及其旧分镜仅为历史参考，不能复用其时长、分辨率、样例数据、旁白、选择器或语音配置。

## 1. 本片要解决什么

本片演示管理员完成两类基础维护：在“系统管理 → 用户管理”中新增一个教师账号并维护其状态（编辑、禁用/启用），在“班级管理 → 学年管理”中新增一个学年。

用户管理是账号与权限的唯一维护入口（管理员/教师两种角色）；学年管理维护 `sys_academic_year`，是班级、分班与学年升级的前置数据。本片只说明这两个业务结果，不承诺替代学校既有的账号审批、人事或学年制度流程。

### 角色与范围边界

- 录制账户为**管理员**，旁白以“管理员”指代操作者（系统管理与班级管理均仅管理员可进入）；不得把操作表述为教师、学生或其他角色。账号信息不出现在画面中。
- 演示页面：系统管理（用户管理 Tab）、班级管理（学年管理对话框）。
- 新建一个**教师角色**的虚构账号与一个**普通学年**（不设为当前学年，避免影响录制环境）；仅使用虚构用户名、姓名、密码与邮箱。
- 不演示：数据备份/恢复、系统设置保存、AI 智能体配置、AI 会话记录、开发者调试（仅开发环境）、关于页、删除账号、重置密码、id=1 超管账号操作、班级管理其他功能。
- 不演示导入、数据库替换、数据抽取、演示 ZIP 修改或产品数据目录写入。`docs/guides/seed-demo-data.md` 仅可作为历史参考，不是本片的执行路径。

## 2. 录制前置条件与安全检查

在打开录制软件前，由执行人逐项确认。任一项不满足时，停止录制并先修正环境，不用剪辑掩盖问题。

| 检查项 | 必须满足的条件 |
| --- | --- |
| 账户与页面 | 已使用管理员账户登录；左侧菜单“系统管理”“班级管理”可见可进入（均仅管理员）。 |
| 数据环境 | 使用可丢弃、可完整恢复的录制数据库；绝不连接生产库或含真实人员信息的库。 |
| 账号唯一性 | `[新用户名]` 与库中现有用户不冲突（用户名唯一，重复会创建失败）；录制环境中不存在同名账号。 |
| 学年唯一性 | `[新学年值]`（格式如 2027-2028）与 `sys_academic_year` 现有学年不冲突（重复会提示“该学年已存在”）；新增时保持“设为当前学年”关闭，不改变录制环境的当前学年。 |
| 运行状态 | 页面加载完成、无报错提示、浏览器/系统通知关闭，缩放和字体在 16:9 画面中清楚可读。 |
| 回滚 | 已明确录制结束后的恢复方式：还原该可丢弃数据库（含本次账号与学年）或按既有安全流程清理；不得对真实库做清理。 |

运行时只使用以下占位符替换为已核验的实际值，不在脚本中预设具体用户名、密码或学年：

- `[新用户名]`
- `[姓名]`
- `[密码]`
- `[邮箱]`（可选）
- `[新学年值]`（格式 `YYYY-YYYY`，不与现有学年冲突）

### 2.1 录制效率提示

- **批次**：A-3（紧随第 1、2 支；新增学年与第 2 支的 `[新学年]` 呼应）。
- **预置**：`[新用户名]`、`[新学年值]` 均不与现有冲突。
- **一次通过要点**：①学年管理在"班级管理"页（不在系统设置）；②新增学年保持"设为当前学年"关闭；③用户密码字段仅新增模式显示。
- **净录制预估**：约 30 分钟/遍。


## 3. 画面、操作与后期总规则

### 3.1 画面规格

- 成片画布为 **16:9**，建议交付 `1920 × 1080`；若源窗口比例不同，应在录制前调整可见区域或后期裁切，不能拉伸界面。
- 录制原始画面时关闭系统声音、应用提示音和通知；录屏只保留清晰的界面操作，AI 旁白在后期单独合成。
- 每个镜头只表达一个意图。页面、下拉菜单和对话框完全稳定后再开始操作；不录入加载抖动、无关菜单或鼠标试探。
- 需要突出字段时仅做克制的局部放大，放大前后保留页面方向感；不使用快速摇镜、夸张缩放或遮挡主要操作区的特效。

### 3.2 鼠标与停留规则

- 鼠标沿短路径移动，点击后离开关键文字；不要绕圈、反复悬停或用光标代替旁白。
- 打开页面、下拉列表或对话框后停留约 **1 秒**，让观看者看清标题和内容。
- 镜头 3、6 的对话框字段较多，各段之间可用跳剪压缩；每个输入与选择稳定后再继续。
- 成功提示（“用户添加成功”“用户更新成功”“学年创建成功”）保留 **0.8–1.5 秒**，随后再切换下一步。
- 出现任何可见错误、重复校验、错误数据、误点击或个人信息时，**从该镜头开头重录**；不要以裁切、马赛克或加速掩盖操作错误。

### 3.3 旁白与字幕规则

- 旁白使用经试听通过的中文 AI 声音；本包不指定具体供应商、声音名称或固定语速。
- 旁白应说明“为什么做”和“操作结果”，不逐字念出每次鼠标点击；画面中的按钮和字段由字幕辅助定位。
- 字幕与旁白同义、逐镜头校时。每条最多两行，避免遮挡表格、表单字段、对话框底部按钮及成功提示。
- 术语以实时构建为准：如录制构建调整了文案（含更换用户名或学年），可替换字幕中的对应词，但不得改变“新增账号 → 维护状态 → 新增学年 → 列表回查”的业务顺序。

## 5. 录制执行清单

1. 按第 2 节完成可恢复环境检查，记录全部运行时占位符的实际值。
2. 先静音录一遍完整画面；仅检查流程、隐私、光标和停留，不在此阶段生成旁白。
3. 回看原始录屏：任何数据泄露、加载异常、错误提示、误点“删除账号”“重置密码”“数据备份/恢复”或“设为当前学年”、误入系统设置/AI 页签、或未能回查新账号与新学年，都从受影响镜头开头重录。
4. 依据第 4 节生成 AI 旁白，先输出可试听音频，再与已确认的画面匹配；不要直接把未经试听的 TTS 音频导出为成片。
5. 依据字幕列制作字幕，逐句检查进入和离开时间；字幕出现应略早于或与对应动作同时，不应滞后到下一步。
6. 完成合成后，从头无中断观看一次；验收通过才导出交付版。录制结束后立即按预先确认的可恢复流程恢复环境。

## 6. 音频、剪辑与导出门禁

### 6.1 音频试听门禁

在最终合成前，至少由录制者完整试听一次 AI 旁白，并逐项通过：

- 声音自然、适合面向学校管理员的说明语气；
- 语速能让观看者同时看清表单、字段和操作，关键停顿自然；
- 音量在全片一致，未被系统声、背景音乐或提示音覆盖；
- “系统管理”“用户管理”“新增用户”“用户名”“姓名”“密码”“角色”“管理员”“教师”“邮箱”“编辑”“禁用账号”“启用账号”“班级管理”“学年管理”“新增学年”“设为当前学年”等中文术语发音正确；
- 无漏读、重读、截断、机械连读或难以辨识的词句。

任一项不通过时，只重生成或重校该段音频并复听；不要通过过度加速、压缩静音或堆叠背景音乐掩盖问题。

### 6.2 画面与字幕门禁

- 每个镜头都可独立看懂一个意图，转场不打断一次新增、编辑、切换或回查动作。
- 关键页面标题、统计卡、表格、表单字段、按钮“新增用户”“确定”“编辑”“禁用账号”“启用账号”“学年管理”“新增学年”和成功提示在 16:9 画面中可读。
- 字幕不遮挡表格、表单字段、对话框底部按钮或成功提示；无错别字、占位符、旧产品名称或历史样例数据。
- 成片不得出现真实个人数据、管理员账号、令牌、文件路径、通知横幅、调试窗、密码管理器或录制工具控件；录制的用户为虚构账号。
- 导出为可播放的 16:9 MP4（H.264 视频与 AAC 音频为推荐兼容组合）；导出后使用独立播放器从头试听、查看字幕和核验总时长。

## 8. 当前实现依据与维护说明

界面文案或业务规则变动时，先以当前代码和实际构建复核，再同步更新本包；不要反向用本包覆盖当前产品事实。
