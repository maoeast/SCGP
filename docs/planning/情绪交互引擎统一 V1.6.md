  v1.7 详细技术设计稿

  1. 设计目标
  v1.7 的目标不是改业务模型，而是统一运行时执行层。

  目标结果：

  - 资源层 JSON 继续按 EmotionSceneResourceMeta / CareSceneResourceMeta 维护
  - 页面不再自己拼 steps
  - 所有交互流程统一编译成 EmotionalSessionConfig
  - 一个 EmotionalInteractionEngine.vue 同时驱动两个子模块
  - 步骤 UI 改为 stepType -> renderer 的多态映射

  2. 分层设计

  资源层
  只面向内容生产与资源管理。

  - EmotionSceneResourceMeta
  - CareSceneResourceMeta

  约束：

  - 数据团队只维护这一层
  - 不允许在资源 JSON 中直接写运行时字段如 phase、stepType

  编译层
  负责把资源层转成运行时层。

  新增两个 adapter：

  - compileEmotionScene(meta, ctx) => EmotionalSessionConfig
  - compileCareScene(meta, ctx) => EmotionalSessionConfig

  编译规则：

  - emotion_scene:
      - intro
      - emotion choice
      - prompts[] 映射为多个 reasoning_question
      - solutions[] 映射为一个 solution_choice
  - care_scene:
      - intro
      - utterances[] 映射为 care_utterance
      - receiverOptions[] 映射为 receiver_preference

  运行时层
  统一只认 EmotionalSessionConfig。

  建议新增：

  - /E:/VSC/H5/SIC-ADS/src/components/emotional/engine/EmotionalInteractionEngine.vue
  - step-renderer-map.ts

  Engine 只负责：

  - 启动 useEmotionalSession
  - 读取当前 step
  - 显示进度
  - 提示升级
  - 反馈面板
  - 完成 / 取消 / summary 跳转

  Engine 不负责：

  - DB 查询
  - 资源 JSON 解释
  - 业务特化步骤拼装

  渲染层
  按 stepType 分发 renderer。

  建议映射：

  - emotion_choice -> EmotionSelector
  - reasoning_question -> ReasoningCard
  - solution_choice -> ReasoningCard
  - care_utterance -> CareOptionCard
  - receiver_preference -> CareOptionCard
  - scene_intro -> SceneIntroStep
  - 需要视角提示时挂 PerspectiveSwitchView

  核心原则：

  - renderer 吃标准 step props
  - 子模块差异放到 metadata
  - renderer 不直接依赖原始 resource meta 结构

  页面层
  两个页面退化成壳层：

  - /E:/VSC/H5/SIC-ADS/src/views/emotional/EmotionSceneTraining.vue:312
  - /E:/VSC/H5/SIC-ADS/src/views/emotional/CareExpressionTraining.vue:350

  壳层职责：

  - 读取 sys_training_resource
  - 反序列化 meta_data
  - 调 adapter
  - 渲染 Engine

  4. Adapter 详细规则

  compileEmotionScene(meta)
  输入：EmotionSceneResourceMeta

  输出步骤顺序：

  1. scene_intro
  2. emotion_choice
  3. meta.prompts 全部转 reasoning_question
  4. solution_choice

  编译规则：

  - targetEmotion -> correctValues
  - prompts[].options[].isCorrect -> correctValues
  - prompts[].options[].isAcceptable -> acceptableValues
  - solutions[].suitability === 'optimal' -> correctValues
  - solutions[].suitability === 'acceptable' -> acceptableValues
  - feedbackText / explanation 写入 option.metadata

  compileCareScene(meta)
  输入：CareSceneResourceMeta

  输出步骤顺序：

  1. scene_intro
  2. care_utterance
  3. receiver_preference

  编译规则：

  - preferredUtteranceIds -> correctValues
  - utterances[].type === 'advice' 可按当前实现进入 acceptableValues
  - receiverOptions[].isComforting === true -> correctValues
  - effect / receiverReactionText / receiverReactionEmoji / reasonText 写入 option.metadata

  6. metadata 约定
  为了避免 renderer 直接反查原始资源，统一约定 metadata 字段：

  scene_intro.metadata

  - variant: 'emotion_scene' | 'care_scene'
  - title
  - description
  - clues?
  - speakerPerspectiveText?
  - receiverPerspectiveText?
  - sceneVisual?

  emotion_choice.metadata

  - targetEmotion
  - emotionColorHex
  - emotionColorLabel

  reasoning_question.metadata

  - questionType
  - feedbackMode?: 'gentle'

  solution_choice.metadata

  - displayMode: 'solution'

  care_utterance.metadata

  - utteranceType
  - effect
  - receiverReactionText
  - receiverReactionEmoji

  receiver_preference.metadata

  - reasonText
  - isComforting

  export type EmotionalSubModule = 'emotion_scene' | 'care_scene'

  export type EmotionalResourceType = EmotionalSubModule

    | 'sad'
    | 'embarrassed'
    | 'angry'
    | 'scared'

  export type EmotionalReasoningQuestionType = 'cause' | 'need' | 'empathy'

  export type EmotionalSolutionRank = 'optimal' | 'acceptable' | 'inappropriate'

  export type EmotionalCareType = 'empathy' | 'advice' | 'action'

  export type EmotionalSessionType =
    | 'game_session'

  export type EmotionalStepType =

  export type EmotionalPerspective = 'sender' | 'receiver' | 'none'

  export type EmotionalFeedbackCode =
    | 'correct'
    | 'acceptable'
    | 'retry'
    | 'guided'
    | 'modelled'
