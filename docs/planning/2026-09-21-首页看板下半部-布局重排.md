# 首页看板下半部布局重排（今日训练日程 / 本周异常预警 / 智能特教助理）

> 状态：已实现（2026-09-21）。本文是首页看板下半部**三面板布局与容器行为**的唯一真源。
> 三个面板的**判定口径**不在本文：异常预警见《2026-09-21-首页本周异常预警-判定口径.md》，智能特教助理见《2026-09-21-首页智能特教助理-评估缺口与干预建议.md》；改布局不得动口径。

## 1. 动机

下半部三面板的观感问题（2026-09-21 用户提出）：

1. 今日训练日程单列平铺：卡片横向过度拉伸，卡片中部大面积留白。
2. 本周异常预警空态：空态与有数据时占用同一固定高度，纵向空间被白占。
3. 智能特教助理：被上方区块挤压，评估建议文字与能力标签密度高、阅读局促。

目标：保持左右分栏，把左侧做成双列卡片网格，右栏上部高度自适应、下部吃满剩余空间。

## 2. 布局结构（规范面 = 现状）

- **显示上限**：三个面板统一为 4 条（`slice(0, 4)`），超出部分经面板「查看全部」弹窗查看；日程双列网格因此正好 2×2。
- **看板分栏** `.dashboard-board`：`grid-template-columns: minmax(0, 65fr) minmax(320px, 35fr)`，`gap: 20px`。左右 65:35；右栏保底 320px。视口 ≤1280px 时折为单列（既有媒体查询保持不变）。
- **左侧今日训练日程** `.schedule-list`：CSS Grid 双列 `repeat(2, minmax(0, 1fr))`，`gap: 16px`。
  卡片 `.schedule-item` 分两段、纵向排列：
  - `.schedule-item__head`：左头像 + 右侧上下两行（`.schedule-item__topline` 姓名 + 模块标签、`.schedule-item__plan` 计划名称）；
  - `.schedule-item__foot`：`margin-top: auto` 贴底并加虚线上边距；左为次要信息 `.schedule-item__meta`（周期 / 资源 / 首项，12px `--scgp-subtle` 浅色小字、可换行），右为主按钮 `.schedule-item__actions`（「开始训练」，`white-space: nowrap`）。卡片等高由网格行拉平，按钮随内容长短贴底对齐。
- **右栏堆叠** `.dashboard-board__stack`：`display: flex; flex-direction: column; gap: 16px; min-height: 0`。
  - `.alert-panel--anomaly`（本周异常预警）：`flex: 0 0 auto` —— 高度完全随内容。
  - `.alert-panel--assistant`（智能特教助理）：`flex: 1 1 auto; min-height: 0`，其 `.alert-list` 追加 `flex: 1 1 auto; min-height: 0; overflow-y: auto; overscroll-behavior: contain`（并 `padding-right: 6px; margin-right: -6px` 给滚动条留位）—— 占满右栏剩余纵向空间，空间不足时面板内滚动。
- **异常预警空态** `.alert-empty`：紧凑横幅（`min-height: 88px`），内容仅两件——`.alert-empty__badge` 图标徽标（42×42 圆角块 + `CircleCheck`）与 `.alert-empty__text`「本周干预数据平稳」。不再使用 `el-empty`。
- **智能特教助理可读性**：`.alert-panel--assistant .alert-item__desc` 行高 1.55、上下外边距 `4px 0 6px`；标签行 `.alert-item__tags` = `display: flex; flex-wrap: wrap; align-items: center; gap: 6px`。行内元素两类：病种名带 `alert-item__tag alert-item__tag--never`（中性灰药丸，与「查看全部」弹窗同一形态），能力标签带 `alert-item__tag--<kind>`（偏弱 / 需关注 / 缺口 / 未评估 / 超期），两者同处一行、随栏宽换行。

## 3. 响应式降级

日程双列 → 单列按**面板自身宽度**判定，不按视口：

```css
.schedule-panel { container-type: inline-size; container-name: schedule-panel; }
@container schedule-panel (max-width: 615px) {
  .schedule-list { grid-template-columns: repeat(auto-fit, minmax(min(300px, 100%), 1fr)); }
}
```

为何用容器查询而不是媒体查询：同一视口宽度下，左栏宽度还取决于看板是否已折为单列（≤1280px 折单列后左栏反而变宽），媒体查询会把这两种情形判错。615px = 两列各 300px + 16px 间距的临界值。

Chromium 实测（252px 侧边栏 + 24px 页内边距的壳）：

| 视口 | 看板宽 | 左栏 / 右栏 | 日程列数 |
|---|---|---|---|
| 1600 | 1300 | 832 / 448 | 双列（384px） |
| 1366 | 1066 | 680 / 366 | 双列（308px） |
| 1281 | 981 | 625 / 336 | 单列（577px，面板内容宽 576 < 615 触发降级） |

## 4. 边界与取舍

- **内部滚动的生效条件**：右栏被约束时才滚动（左栏更高、右栏被拉伸后空间仍不足，或将来给看板加高度上限）。当右栏内容本身高于左栏时，网格行高由右栏决定 → 页面自然滚动，不截断内容。两种情形都不隐藏信息；代价是「极端情况下不会出现面板内滚动条」。
- **右栏保底 320px** 是硬下限：低于该宽度时 65:35 不再成立，由 `minmax` 的 px 下限接管（防挤压优先于比例）。
- 日程卡在超宽屏（左栏内容宽 >1300px）仍保持双列，卡片会变宽——双列是明确目标，未开放第三列。

## 5. 不做什么

- 不动三个面板的判定口径、取数接口（`dashboard-api.ts`）、「查看全部」行为与标题/描述/角标文案（显示上限见 §2）。
- 不动看板上半部分（`.dashboard-hero`、指标卡、AI 助手区、最近添加的学生、训练进度概览）。
- 不引入 CSS 框架/Mock 数据组件：改动落在真实 `src/views/Dashboard.vue`。
