将下方提示词交给 Claude 或 Gemini，并附上 `2026-11-04-scgp-tablet-apk-draft.md`。有仓库访问能力时同时提供当前 SCGP 仓库；没有时，请其明确哪些结论需要回代码确认。

```text
请独立审查《SCGP 平板现场训练端：产品与技术初稿 v0.1》。本轮只审查，不实施代码。

用户已确认：
1. Android APK，首版包含今日任务、学生速查、生活自理执行、器材训练记录、近期回看、局域网访问与离线暂存。
2. 整体颜色和 UI 风格与 PC 保持一致，布局符合平板操作逻辑。
3. 学校一台 PC 提供局域网数据服务，多位老师同时使用多台平板。
4. 两端共用 PC 已有教师账号，同一平板支持不同教师登录和切换。
5. 不要过度设计和防御。先打通业务，不扩展复杂同步、云账号、庞大权限或测试体系。

请阅读初稿中的当前代码事实。能访问仓库时，针对会改变结论的关键点核对实际源码；不要把提议当作已实现。

重点审查：
- Vue/TS/Vite/Pinia + Capacitor + SQL.js 是否适合当前范围。
- PC 现有公共 token 和自理场景主题的复用是否正确。
- 平板的记录动作是否足够少，老师是否能顺畅连续操作。
- 远端教师会话是否会误用或改变 PC 当前登录人。
- Main 局域网服务通过 IPC 访问 Renderer 唯一数据实例是否可行。
- 保存、回传、两类评分与计划来源是否能进入现有记录体系。

请输出：
1. 结论：可进入首个闭环验证 / 修改哪些事项后再进入。
2. 最多 5 项必须修改的问题。每项给出初稿位置、证据、影响和最小修改建议。
3. 最多 3 项可简化或可删除的设计。
4. 没有依据的担忧注明“待验证”，不要当成确定缺陷。

Claude 可重点检查源码复用与数据链；Gemini 可重点检查产品范围、视觉连续性与现场交互。但两者都需要检查整条业务是否成立。

不要因为未来可能需要某能力而要求首版新增。不要直接安装依赖、改代码、提交或部署。
```
