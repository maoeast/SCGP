**任务**：为认知发展（cognitive）训练入口新增一批纯认知训练小游戏，填补现有游戏库在"工作记忆 / 执行功能 / 逻辑推理 / 数感"等核心认知范式上的空白。

## 1. 全局约束（继承，不重复展开）

本游戏包**完全继承** `docs/planning/2026-03-20-emotion-games-prd.md §一` 的全部硬约束，仅列认知专属增量：

| 约束 | 认知专属说明 |
|------|--------------|
| 资产策略：内联 SVG + CSS transform/keyframes；物理效果 canvas；禁纯 CSS 画复杂人物动物 | 认知游戏以**几何形 / 符号 / 网格 / 卡片**为主，天然适合纯 SVG/CSS，素材成本最低 |
| 通用容器 `GameContainer.vue`：左上退出 / 右上设置 / 统一 `onGameComplete` 写库 | 认知游戏复用同一容器，`onGameComplete` payload 需带认知特有指标（见 §3.3） |
| 无障碍：禁 >3Hz 闪烁；温和错误反馈（禁红叉刺耳音）；热区 ≥64px | **额外**：认知游戏的"答错"反馈尤其要避免挫败感——用"再想一想"轻提示 + 选项轻微弹回，绝不计时扣分到负（见各游戏反馈节） |
| 素材版权：95% 代码生成；图标 Tabler/Heroicons；插画 unDraw；真图 Picsum | **额外**：认知 52 器材 webp 为**用户自有 CSV 配套图**，零版权风险，可作"物品认知"类游戏的实物素材池（这是认知包相对情绪包的素材优势） |
| 三级难度：L1 无干扰/极慢/100% 容错；L2 少量干扰；L3 多重干扰/连续正确 | 认知游戏难度递进轴**按认知负荷量化**（对数 / 物品数 / 序列长度 / 干扰项数），见 §2.2 |
| **色彩编码冗余**：凡靠颜色区分选项的游戏，需同时提供形状或图案冗余编码，不能仅靠颜色传递信息 | 服务色弱/色盲儿童；K03/K05/K09 高度依赖颜色，必须叠加形状/图案维度 |
| **拖拽交互备用路径**：凡拖拽类操作，需提供"点选起点→点选终点"等效备用交互路径 | 服务精细动作困难儿童；K05/K06/K10 必须提供（可参考 K08 已有的"方向键/点击下一步"备选模式） |

## 2. 认知能力域框架与映射

### 2.1 训练目标分类轴（每个游戏标注其主训练域）

| 能力域 | 内涵 | 涉及游戏 |
|--------|------|----------|
| **工作记忆** Working Memory | 暂存并操作信息（视觉/听觉/序列） | K01 K02 K09 |
| **执行功能** Executive Function | 抑制、刷新、计划、认知灵活性 | K02 K05 K08 K10 |
| **逻辑推理** Reasoning | 规律、分类、因果、关系判断 | K03 K04 K10 |
| **数感** Number Sense | 基数、序数、多少、增减 | K05 K06 |
| **感知辨别** Perception | 视觉/听觉细节辨别、选择性注意 | K07 K09 |
| **空间认知** Spatial | 方位、路径、心理排序 | K06 K08 |

### 2.2 三级难度统一设计原则

所有认知游戏遵循"**认知负荷量化递进**"，三个维度任一递增即升档：
- **信息量**：物品数 / 卡片对数 / 序列长度 / 选项数
- **干扰**：相似度递增的干扰项 / 死胡同 / 无关变量
- **时间/保持**：展示时长缩短 / 需连续正确 / 反向复现

> 默认 L1 起步，教师在 GameContainer 设置面板手动调档；L1 永远 100% 容错（无"答错"惩罚，仅温和提示），保护特教儿童自我效能感。

### 2.3 与认知 52 器材资源 / CSV 类别的映射

认知器材 CSV 的 8 大类别（基础配对 / 物品认知 / 人物与身体 / 动作与场景 / 特征与逻辑 / 情绪与社交 / 综合认知活动 / 教学支持）+ 每条器材的「能力标签」，是本游戏包**内容驱动**的天然素材源：

| 游戏 | 可驱动的 CSV 类别 / 能力标签 |
|------|------------------------------|
| K01 记忆翻牌 | 基础配对类 / 物品认知类（卡片正面 = 器材图） |
| K02 少了什么 | 物品认知类 / 综合认知活动 |
| K04 哪个不同类 | 特征与逻辑类 / 物品认知类（"能力标签"即类别锚） |
| K05 数感小铺 | 综合认知活动（器材当计数物） |
| K07 找不同 | 综合认知活动（器材场景图） |
| K10 因果排序 | 动作与场景类（步骤序列素材） |

→ **落地优势**：物品类游戏的素材图可直接从 `src/assets/images/physical-equipment/cognitive/*.webp` 按能力标签筛选复用，无需新做美术。

## 3. 命名、接入与库表约定

### 3.1 gameCode 命名：K 系列

现有前缀按训练入口分（G=emotional, F=fine-motor, S=social, C=soothing, L=life-skills）。cognitive 首字母 C 与 soothing 的 C 冲突，**本 PRD 采用 `K` 系列**（K = Knowledge/认知，认知评估领域常用前缀如 K-ABC，且零冲突）：

```
K01_MEMORY_MATCH   K02_MISSING_ITEM   K03_PATTERN_NEXT   K04_ODD_ONE_OUT   K05_NUMBER_SENSE
K06_SIZE_ORDER     K07_SPOT_DIFF      K08_MAZE_RUN       K09_ECHO_SEQ      K10_STORY_ORDER
```

### 3.2 registry 接入约定（实施时直接套）

每个游戏在 `src/data/custom-game-registry.ts` 新增一条 `CustomGameDefinition`，关键字段固定：

```ts
moduleCode: ModuleCode.COGNITIVE,
trainingEntryCode: 'cognitive',
entryPath: '/emotional/games/<slug>',   // 见 §3.4 待决策
maxPlayers: 1,                           // 认知游戏默认单人
requiredPermissions: [],                  // 本批 10 个均无需 camera/mic
permissionPolicy: 'all_required',
difficultyLocked: false,
// metadata 含: emoji / color / duration / difficulty / therapeuticGoal
//             / previewDescription / repeatPlayHint / cognitiveLoad
```

### 3.3 库表落点（已核对 unified schema 现状，见 §7-1）

`game_emotion_records` 为 emotional 专用、且属 unified schema 待收口的旧表。认知游戏记录落点：

- **方案 A（新建 `game_cognitive_records`）**：与 emotional 旧表对称——但与 `docs/planning/2026-04-01-unified-training-record-schema-plan.md` §3.2「不继续新增用户可见主记录表 / 不采用一游戏一张表」**直接冲突**，**不推荐**。
- **方案 B（推荐）**：接入**统一训练记录主表 `training_session`** + 游戏家族明细表（复用 `training_session_game_detail`，或认知特有指标多时新增 `training_session_cognitive_game_detail`），复用已有 `TrainingSessionWriter`。已核对：`training_session` 表与统一 writer 已在 `src/database/init.ts` + `src/database/training-session-writer.ts` 落地（非纯计划态），认知游戏以 `module_code='cognitive'` / `session_family`（建议 `cognitive_game`）写入即可，授权与筛选走 `module_code` / `entry_code`，无需独立建表。

`training_session` 主表已含 `accuracy_rate` / `avg_response_time_ms` 摘要字段，认知特有指标（范式标签 `paradigm`、难度级、本局参数）放 `summary_payload`（JSON）。`summary_payload` 至少含：`paradigm`（范式标签，便于跨游戏聚合）/ `difficultyLevel` / `correctCount` / `totalCount` / `avgResponseMs` / **`actualParams`（本局实际生成参数，IEP 追踪必需，见下段）**。

> **【已定 B / IEP 级可追踪】**`summary_payload` 除 `difficultyLevel` 标签外，**必须记录本局实际生成的参数值**（如 K01 本局网格大小/对数、K09 本局序列长度、K04 本局干扰项数、K03 本局规律类型与序列长度等具体数字）。原因：同一 `difficultyLevel` 标签下不同局的实际难度不等价，"响应时间从 2.3s 降到 1.5s"这类跨局对比会失真——无法区分是孩子进步还是该局题目恰好更简单。各游戏 `actualParams` 的精确字段在 K03 实施方案中定稿后回填本节。

### 3.4 entryPath 命名空间（待决策，见 §7-2）

现有所有 custom 游戏（含 sensory/social/life-skills）entryPath 都塞在 `/emotional/games/<slug>` 下，是历史遗留。两选一：
- **方案 A（务实，零路由改动）**：沿用 `/emotional/games/<slug>`，与现有 25 个游戏一致；
- **方案 B（语义干净）**：新建 `/cognitive/games/<slug>` 命名空间，需在路由表注册。

PRD 暂按方案 A 写（slug 见各游戏节），最终随 §7-2 决策调整。

> **方案 A 的技术债触发条件**（若本次仍选 A）：sensory/social/life-skills 已因"零路由改动"沿用 `/emotional/games/`，cognitive 若跟进将是第 4 次延续这个临时决定。为避免无限期延续，设明确重构触发条件：**当 custom 游戏总数超过阈值（建议 40 个），或下次需要做跨 entry 的路由级功能（如统一游戏搜索、跨模块推荐）时，必须把所有 custom 游戏 entryPath 迁移到按 entry 分的命名空间**（`/cognitive/games/`、`/sensory/games/` 等），不再不设条件地"以后再说"。

## 4. 十个游戏详细 PRD

> 每个游戏统一模板：定位 → 玩法 → 三级难度 → 交互与反馈 → 素材来源 → 无障碍注意 → 元数据（可直接抄进 registry）

---

### K01_MEMORY_MATCH · 记忆翻牌（找成对）

- **定位**：视觉工作记忆经典范式（Concentration/Memory）。认知价值★★★★★，素材成本极低，**P0**。
- **能力域**：工作记忆 / 感知辨别
- **玩法**：N 对卡片背面朝上铺成网格；孩子翻两张，相同则保留并亮起，不同则翻回；全部配对完成即过关。
- **三级难度**：

| 级别 | 网格 | 对数 | 干扰 | 容错 |
|------|------|------|------|------|
| L1 | 2×2 | 2 对 | 无；翻错不翻回（保持翻开降低负荷） | 100% |
| L2 | 3×4 | 6 对 | 翻错 1.2s 后翻回 | 任意次 |
| L3 | 4×4 | 8 对 | 翻错翻回 + 相似图干扰（同类别不同物） | 步数计星级 |

- **交互与反馈**：配对成功 → 卡片发光 + 温和"叮"；配对失败 → 两张卡片轻微摇头后翻回，**无扣分无红叉**；热区 ≥72px（整张卡）。
- **素材来源**：卡片正面 = 程序化 SVG 几何图形（形状/颜色/图案组合）或认知 52 器材 webp 缩略图（物品认知模式）；卡背 = 统一 SVG 花纹（CSS 生成）。
- **无障碍注意**：翻面动画 ≤400ms，禁闪烁；L1 卡片保持翻开是关键降负荷设计。
- **元数据**：
  - `therapeuticGoal: '视觉工作记忆'`，`cognitiveLoad: 'medium'`，`duration: '3-5分钟'`
  - badge: `BADGE_MEMORY_MASTER` / 「记忆小达人徽章」
  - previewDescription: 「翻开两张卡片，找到一模一样的好朋友，把它们都配成对。」
  - repeatPlayHint: 「每次卡片图案、网格和配对组合都会换，越练记得越稳。」

---

### K02_MISSING_ITEM · 少了什么

- **定位**：短时记忆 + 编码刷新（工作记忆刷新范式）。认知价值★★★★，**P1**。
- **能力域**：工作记忆 / 执行功能
- **玩法**：展示一排物品 → 倒计时记忆 → 物品被遮住 → 其中一件消失 → 孩子从候选里选出"少了什么"。
- **三级难度**：

| 级别 | 物品数 | 展示时长 | 消失数 | 候选干扰 |
|--------|--------|----------|--------|----------|
| L1 | 3 | 5s | 1 | 2 选 1 |
| L2 | 4 | 4s | 1 | 3 选 1 |
| L3 | 5 | 3s | 2 | 4 选 1 |

- **交互与反馈**：遮罩用柔和幕布下落动画；选对 → 物品归位 + 星星；选错 → 候选轻轻弹回 + "再想想"，可重选（L1）/ 计入星级（L3）。
- **素材来源**：物品 = 程序化 SVG（水果/日用品/动物图标库，Tabler 风格）+ 可选认知器材 webp。
- **无障碍注意**：展示阶段无任何计时音压迫感；L1 候选仅 2 个、容错 100%。
- **元数据**：
  - `therapeuticGoal: '短时记忆'`，`cognitiveLoad: 'medium'`，`duration: '3-5分钟'`
  - badge: `BADGE_SHARP_EYES` / 「火眼金睛徽章」
  - previewDescription: 「记一记桌上有哪些东西，等它们藏起来后，看看少了哪一个好朋友。」
  - repeatPlayHint: 「每次物品组合、摆放和消失顺序都不一样，让小脑袋越记越清楚。」

---

### K03_PATTERN_NEXT · 模式补全

- **定位**：规律推理（序列模式完成），逻辑思维入门。认知价值★★★★★，素材成本最低（纯几何），**P0**。
- **能力域**：逻辑推理
- **玩法**：一排按规律排列的图形留一个空位，孩子从底部候选选出"下一个该是什么"。
- **三级难度**：

| 级别 | 规律类型 | 示例 | 候选 |
|------|----------|------|------|
| L1 | AB 交替 | 🔴🔵🔴🔵🔴＿ | 2 选 1 |
| L2 | ABB 重复 / ABC 轮转 | 🔺🔺🔵🔺🔺＿ / 🔴🔵🟡🔴🔵＿ | 3 选 1 |
| L3 | 递进 / 复合 | 🔵🔵🔵（数量+1）→ 大小/数量双重维度 | 4 选 1 |

- **交互与反馈**：序列横向排列 + 空位脉冲提示；选对 → 图形落入空位 + 整条序列顺次高亮"读"一遍（强化规律感知）；选错 → 候选弹回 + 教师可选"读一遍规律"提示音。
- **素材来源**：100% 程序化 SVG（颜色/形状/大小三维度组合），零图片。
- **无障碍注意**：序列高亮"读"一遍的速度 ≤1 题/秒，禁快闪；选项靠颜色区分时必须叠加形状/图案冗余编码（见 §1「色彩编码冗余」），不可仅靠颜色传递规律。
- **元数据**：
  - `therapeuticGoal: '规律推理'`，`cognitiveLoad: 'medium'`，`duration: '3-5分钟'`
  - badge: `BADGE_PATTERN_PRO` / 「规律小侦探徽章」
  - previewDescription: 「看看这排图形是按什么规律排的，猜猜空着的那个位置应该放什么。」
  - repeatPlayHint: 「每次的规律、图形和颜色都会变，越练越能看出藏起来的小秘密。」

---

### K04_ODD_ONE_OUT · 哪个不同类

- **定位**：语义归类 / 认知灵活性（概念形成）。认知价值★★★★，**P0**。
- **能力域**：逻辑推理 / 概念形成
- **玩法**：一组物品中有一个不属于同类，孩子把它找出来（点选或拖到"不同类"筐）。
- **三级难度**：

| 级别 | 数量 | 类别差异 | 示例 |
|------|------|----------|------|
| L1 | 3 选 1 | 大类不同 | 苹果、香蕉、汽车 → 汽车 |
| L2 | 4 选 1 | 细分类别 | 猫、狗、兔、玫瑰 → 玫瑰 |
| L3 | 5 选 1 | 抽象/功能维度 | 飞机、鸟、蝴蝶、风筝、鱼 → 鱼（其余会飞） |

- **交互与反馈**：选对 → 该项柔和浮起进筐 + "分类正确"；选错 → 弹回 + "再看看它们有什么一样"，L1 可重选。**L3 答对后**，系统追加一句简短归类依据说明（如"其他几个都会飞哦"），帮助孩子建立可迁移的分类规则理解，而非仅给出对/错判定——隐性功能分类规则通常需显式教学才能真正掌握，单纯靠试错容易"蒙对"而非真懂。
- **素材来源**：物品 = 程序化 SVG 图标库（按类别分组：动物/植物/食物/交通/日用品）+ 可选认知器材 webp（按能力标签筛选，CSV「类别名称」直接当类别锚）。
- **无障碍注意**：L3 的"抽象维度"对低龄偏难，教师可关闭仅玩 L1-L2。
- **元数据**：
  - `therapeuticGoal: '语义归类'`，`cognitiveLoad: 'medium'`，`duration: '3-5分钟'`
  - badge: `BADGE_CATEGORY_STAR` / 「分类小专家徽章」

### K05_NUMBER_SENSE · 数感小铺（按数取物 + 多少比较）

- **定位**：数感奠基（基数 / 多少 / 增减），数理认知入门。认知价值★★★★★，**P0**。
- **能力域**：数感 / 执行功能
- **玩法（双模式，教师选）**：
  - 模式 A 按数取物：屏幕给数字 N，孩子拖 N 个物品进筐；
  - 模式 B 多少比较：两组物品，选"哪边多 / 哪边少 / 一样多"。
- **三级难度**：

| 级别 | 模式 A 数字范围 | 模式 B 数量差 | 进阶 |
|------|-----------------|---------------|------|
| L1 | 1–3 | 差大（2 vs 5） | 仅"多/少" |
| L2 | 1–5 | 差小（3 vs 4） | 加入"一样多" |
| L3 | 1–10 | 含相等判断 | 模式 A 加入"再多放 2 个 / 拿走 1 个"的增减指令 |

- **交互与反馈**：拖入筐 → 物品落入 + 计数器跳动报数（同步语音"1、2、3"强化基数）；取错 → 物品弹回 + 筐轻晃；多少比较选错 → 两组物品逐个配对连线可视化"多出来的部分"。
- **素材来源**：计数物 = 程序化 SVG（苹果/星星/球，可换皮肤）+ 可选认知器材 webp；数字 = 大字号 SVG/CSS。
- **无障碍注意**：计数语音清晰缓慢；"多出来的部分"连线可视化是 L3 关键脚手架，非惩罚；选项/物品靠颜色区分时叠加形状冗余编码（见 §1「色彩编码冗余」）；拖拽取物需提供"点选起点→点选终点"备用路径（见 §1「拖拽交互备用路径」）。
- **元数据**：
  - `therapeuticGoal: '数感奠基'`，`cognitiveLoad: 'medium'`，`duration: '3-6分钟'`
  - badge: `BADGE_LITTLE_COUNTER` / 「数数小能手徽章」
  - previewDescription: 「看看数字是几，就拖几个好朋友进小筐；或者比一比哪边的更多、哪边的更少。」
  - repeatPlayHint: 「每次的数字、物品和比较方式都会换，让小脑袋慢慢学会数和比。」

### K09_ECHO_SEQ · 序列复现（灯光/声音 Simon）

- **定位**：序列工作记忆（Corsi / Simon Says 范式），听觉+视觉双通道。认知价值★★★★，**P1**。
- **能力域**：工作记忆（序列）/ 感知辨别
- **玩法**：系统按顺序点亮一组彩色按钮（每个配一个音高），孩子按相同顺序复现。
- **三级难度**：

| 级别 | 序列长度 | 按钮/颜色数 | 进阶 |
|------|----------|-------------|------|
| L1 | 2 | 2 | 顺序复现 |
| L2 | 3–4 | 3 | 顺序复现 |
| L3 | 5–6 | 4 | 顺序 + 反向复现（教师开关） |

- **交互与反馈**：系统亮灯 400ms/个，间隔 200ms；孩子按对 → 该钮亮 + 发声；按错 → 序列重播一遍 + "再听一次"，无惩罚；通关 → 序列越来越长。**设置面板提供"仅视觉模式"与"仅听觉模式"开关**，允许孩子只用单一感官通道完成——服务听觉敏感（自闭症谱系常见）/ 听障 / 视障儿童；K09 是本批认知负荷最高（`cognitiveLoad: 'high'`）的游戏，单通道可及性尤其重要。
- **素材来源**：100% 程序化（SVG 圆形按钮 + Web Audio API 程序化音高，五声音阶避免不协和），零图片零音频文件。
- **无障碍注意**：亮灯频率严格 <3Hz（序列间隔 ≥200ms 即 ≤5/s 但单钮单次不闪，安全）；音量可在设置调；L1 长度 2 保证入门；按钮靠颜色区分时叠加形状/图案冗余编码（见 §1「色彩编码冗余」）。
- **元数据**：
  - `therapeuticGoal: '序列工作记忆'`，`cognitiveLoad: 'high'`，`duration: '3-5分钟'`
  - badge: `BADGE_ECHO_STAR` / 「回声小明星徽章」
  - previewDescription: 「看清楚、听仔细按钮亮起的顺序，然后一模一样地按出来，序列会越来越长。」
  - repeatPlayHint: 「每次的序列、颜色和声音都会变，越练越记得住一长串。」

### K10_STORY_ORDER · 因果排序（纯认知版）

- **定位**：时序 + 因果推理（事件排序）。认知价值★★★★，**P1**。与现有 S03 故事接龙板的区别：S03 偏社交情境叙事，K10 偏纯认知因果（自然/工序），素材与判定独立。
- **能力域**：执行功能（时序）/ 逻辑推理（因果）
- **玩法**：一组打乱顺序的事件卡，孩子按"先发生→最后发生"拖入时间轴。
- **三级难度**：

| 级别 | 卡片数 | 因果类型 | 示例 |
|------|--------|----------|------|
| L1 | 3 | 明显自然因果 | 种子→发芽→开花 |
| L2 | 4 | 含中间工序 | 打蛋→搅拌→入锅→煎熟 |
| L3 | 5 | 相似步骤需精细判断 | 多步且相邻步骤易混 |

- **交互与反馈**：拖入时间轴 → 顺次吸附；全排完后系统按时间轴"播放"一遍事件（强化因果链）；排错 → 该卡弹回 + "再想想谁先发生"，L1 可重排。
- **素材来源**：事件卡 = 程序化 SVG 情境插画（unDraw 风格组件化，自然/厨房/日常系列）；可借鉴 S03 故事接龙板组件结构改造（复用拖拽吸附 + 时间轴骨架，换素材与判定）。
- **无障碍注意**："播放因果链"速度 ≤1 卡/秒；L1 仅 3 卡；拖卡入时间轴需提供"点选起点→点选终点"备用路径（见 §1「拖拽交互备用路径」）。
- **元数据**：
  - `therapeuticGoal: '时序因果'`，`cognitiveLoad: 'medium'`，`duration: '3-6分钟'`
  - badge: `BADGE_STORY_DIRECTOR` / 「故事小导演徽章」
  - previewDescription: 「这些图里藏着一个故事，可是顺序乱了，把它们按先发生、后发生的顺序排到时间轴上。」
  - repeatPlayHint: 「每次的故事、卡片和顺序都会换，越练越会讲清楚先因后果。」
