# 首页看板「本周异常预警」：数据来源与判定口径

> 状态：已实现（2026-09-21）。本文是该面板**判定口径的唯一真源**：数据源、四类信号、阈值、家族白名单、已知取舍与不做什么。
> 涉及代码：`src/database/training-anomaly-rules.ts`（纯函数与常量）、`src/database/dashboard-api.ts#getWeeklyAnomalies`、`src/views/Dashboard.vue`。

## 1. 为什么有这份文档

2026-09-21 排查（用户提问「这个功能有实际数据来源和分析逻辑吗」）发现旧实现有三个缺陷：

1. **扫描源是两张旧表**：`training_records` + `emotional_training_session`。而项目 2026-04-01 起建立统一训练主表 `training_session`（双写已落地），只写统一主表的入口（实测 `cognitive_game_inline` 20 条）完全不进扫描。
2. **情绪训练被切两半**：`training_records` 分支硬排除 `module_code='emotional'`，而情绪分支只覆盖有 `emotional_training_session` 行的记录——实测近 7 天有 **217 条 emotional 训练两头都不看**。
3. **「提示依赖」是条死规则**：判定取 `emotional_training_detail.hint_level` 的均值 > 2，但该明细表在演示库 **0 行**（演示脚本只清不写）→ 规则恒定不触发；实测近 7 天命中 **0 条**，面板必然空态。

## 2. 数据源与职责划分

| 环节 | 真源 | 说明 |
|---|---|---|
| 事实源 | **`training_session`**（统一训练主表） | 统一训练记录计划 Phase B 双写产物；Phase C 明确把「首页训练摘要」列为要切到该表的消费者（`docs/planning/2026-04-01-unified-training-record-schema-plan.md:200-222`） |
| 写入 | `TrainingSessionWriter.upsertSession`（`src/database/training-session-writer.ts`） | 各训练链双写（`ON CONFLICT(source_table, source_record_id)` 幂等） |
| 情绪会话补充字段 | `emotional_training_session`（按 `training_record_id` 1:1 关联） | 取 `hint_count` / `question_count` 算提示依赖 |
| 器材提示层级 | `training_session.summary_payload.promptLevel` | 器材源表无 accuracy 列，只有 `score` / `prompt_level` |
| 教师隔离 | `getCurrentTeacherStudentScope('s')` | 教师仅见任教班级学生 |
| 判定规则 | **`training-anomaly-rules.ts` 的纯函数 `evaluateTrainingAnomaly`** | SQL 只取窗口内的原始行，是否异常由纯函数决定——规则单一真源，可 jiti 单测 |

**覆盖对账（2026-09-21，真实库全库）**：`training_records` 835/835、`equipment_training_records` 186/186、`game_emotion_records` 101/101、`emotional_training_session` 124/124 均有对应统一行，缺口 0；另发现 20 条 `cognitive_game_inline` 只存在于统一主表（旧实现的盲区）。

## 3. 四类信号

窗口：**滚动 7×24 小时**（`ANOMALY_WINDOW_DAYS=7`，非自然周，与看板其它「过去 7 天」口径一致）。

| 信号 | 条件 | 文案 | 适用家族 |
|---|---|---|---|
| 低正确率 | `accuracy_rate < 0.5` | 正确率低于 50% | **白名单**：`game` / `task_training` / `care_scene` / `emotion_scene` / `cognitive_game` |
| 提示依赖 | `hint_count / question_count > 0.5` | 提示依赖较高（平均每题 N 次提示） | `care_scene` / `emotion_scene` |
| 器材高辅助 | `promptLevel >= 4` | 训练需「手触引导/身体辅助」辅助 | `equipment` |
| 训练中断 | `completion_status ∈ {interrupted, aborted, cancelled}` | 训练未完成（中断或退出） | 全部 |

**为什么低正确率用白名单而不是「全部家族」**：`equipment_training_records` 与 `game_emotion_records` **源表没有 `accuracy_rate` 列**，统一主表里的值是得分率（实测器材 `score=2` → 0.4）。直接套阈值会把 55 条器材行的「得分率偏低」误标成「正确率低于 50%」。器材改用提示层级判定；情绪游戏（得分率、无提示数据）暂不纳入，避免无依据阈值。

**提示层级语义**（取自应用自身的等级表 `src/views/equipment/Records.vue` getPromptLevelLabel）：1 独立完成 / 2 口头提示 / 3 视觉提示 / **4 手触引导 / 5 身体辅助**——4、5 为需要身体介入的最高两档。

## 4. 展示与交互

- 面板列出窗口内全部异常（面板固定高度内滚动，不再截断），排序为**「严重度优先，同级按时间倒序」**：训练中断 > 低正确率 > 提示依赖 > 器材高辅助（`ANOMALY_SEVERITY_RANK` + `anomalySeverityRank`）。为何按严重度：器材高辅助在该群体是常态（实测 7 天 76 条），时间倒序会让最靠前的几条全是器材。角标显示窗口内总数；「查看全部」→ 弹窗按同一排序列全量（同样可点进学生详情，Enter/Space 可达）。
- 条目行尾只显示**一个**关键指标，按家族降级取：答对率家族「正确率 X%」→ 器材「提示 N 级 名称」→ 情绪场景「每题提示 N.NN 次」；家族均不适用时退回会话标签。**器材行不显示「正确率」**（避免把得分率误读为答对率）。
- 指标卡「本周异常预警」数字与面板同源（`weeklyAnomalyCount = anomalies.length`）。

## 5. 已知取舍（真实库实测）

- **器材高辅助条目会占多数**：近 7 天命中 86 条 = 器材高辅助 76 + 情绪提示依赖 10（低正确率 0、中断 0——演示数据里 `aborted` 都在 7 天窗口之外）。器材 186 条会话里有 76 条提示层级 ≥4（41%），属该群体的**常态**而非「波动」。
  - 2026-09-21 用户拍板：**先上严重度排序**（已实现，见 §4），**不动阈值**；下面两条仍可选（未排期）：① 阈值升到 5（身体辅助）② 改为相对基线（比该生历史均值高 ≥2 档）——后者需先验证基线质量（小样本学生多），留专门一轮。
- **情绪游戏不参与低正确率判定**：其 `accuracy_rate` 是 `score/maxScore` 得分率；阈值口径需产品先定，未擅自设定。
- 演示数据缺口：`emotional_training_detail` 0 行（演示脚本只清不写），所以任何依赖该明细表的规则在演示环境都无法触发——这也是第 3 条死规则的根因。
- 已知数据口径不一致（**已上报未改**）：演示脚本写入的 `session_family` 是 subModule（`care_scene`/`emotion_scene`），生产写入的是 `emotional_scene`；动它需要重导演示包。

## 6. 守卫与验证

- `scripts/tests/dashboard-anomaly-rules.test.mjs`（`test:core:node`）：① 异常查询必须以 `training_session` 为主表、不得再直扫 legacy 表 ② 阈值/状态枚举必须来自规则模块（不得内联在 SQL）③ 答对率白名单显式排除 `equipment`/`emotional_game` ④ 未完成枚举与统一链文档一致。
- `tests/training-anomaly-rules.test.ts`（`test:core:ts`，7 场景）：家族归属、阈值边界（等于不算异常）、器材等级标签、未完成枚举、多信号文案、缺数据不猜 0、严重度排序。
- 真库只读复算（2026-09-21）：窗口内 1019 行 → **86 条异常**（旧实现 0 条）：器材高辅助 76、情绪提示依赖 10。

## 7. 明确不做（与原因）

- **不做趋势/基线偏离判定**（如「正确率比该生均值下降 X%」）：需要定义基线与置信口径，留给独立专题。
- 不为器材/情绪游戏硬设得分率阈值：得分率与答对率不是一回事，阈值需产品定。
- 不改演示数据（`session_family` 口径不一致、缺 `emotional_training_detail`）：属演示包重建范围（2026-09-21 用户确认不管）。
- 提示层级标签表 `PROMPT_LEVEL_LABELS`（本模块）与 `src/views/equipment/Records.vue` 的同名表暂存两份：2026-09-21 用户定「下一轮统一」，本轮不动 Records.vue。
