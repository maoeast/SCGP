# Self-Care 全屏训练执行页布局设计

> 日期：2026-05-12
> 状态：待用户审阅
> 范围：`src/views/self-care/TaskExecution.vue`
> 目标：将 self-care 全屏训练执行页收敛为“左侧大图主舞台 + 右侧固定记录栏”的无滚动桌面布局。

## 1. 背景

当前 self-care 执行页已经具备以下能力：

- 根据任务和学生上下文进入执行页
- 展示当前步骤文本
- 记录完成等级、错误等级、教师备注
- 展示执行概览统计
- 支持上一步、中断保存、下一步/完成训练

当前问题：

- 当前步骤区仍以文字信息为主，图片没有成为主展示对象
- 页面被拆成“上方执行区 + 下方概览/按钮”，视觉重心分散
- 全屏训练场景下，老师和孩子的关注点不能稳定落在步骤图上
- 如果后续继续叠加内容，现有结构容易走向纵向增长和滚动

本次设计只解决布局和信息层级问题，不修改训练记录语义，不扩展业务流程。

## 2. 设计目标

本次页面改造必须满足：

1. 全屏状态下，一个桌面屏幕内完整展示全部核心内容，不依赖页面上下滚动。
2. 当前步骤图片成为页面主舞台，占据主要版面。
3. 右侧记录栏固定存在，老师能边看图边完成记录。
4. 重要动作与记录字段全部常驻，不通过折叠、切页、弹窗或二级展开获取。
5. 页面整体优先服务执行中场景，不再维持现有“上区 + 下区”的分段结构。

## 3. 设计结论

采用 `B：主舞台 + 记录工作栏` 作为正式落地方向。

页面拆为左右两栏：

- 左侧：当前步骤主舞台
- 右侧：固定记录工作栏

不保留独立顶栏。任务名、学生名、当前第几步等上下文信息并入左右内容区内部。

## 4. 页面结构

### 4.1 总体结构

页面根容器改为固定高度视口布局：

- 页面最小高度：`100vh`
- 页面内部不出现整体纵向滚动
- 主内容区使用双栏 `grid` 或等价布局
- 左栏宽于右栏，初始实现采用约 `1.65 : 0.85` 的双栏比例，并只允许在这个量级内做小幅微调

桌面结构如下：

```text
左侧主舞台 | 右侧固定记录栏
```

### 4.2 左侧主舞台

左侧从上到下分为三个区块：

1. 上下文信息区
2. 当前步骤图片主展示区
3. 步骤导航区

#### 4.2.1 上下文信息区

必须展示：

- 任务名称
- 学生名称
- 当前步骤序号 / 总步骤数

这个区块只保留紧凑信息，不再占用独立顶栏高度。

#### 4.2.2 当前步骤图片主展示区

这是页面视觉中心，必须满足：

- 使用当前步骤的 `imagePath` 作为主图
- 展示策略采用 `contain`，完整保留图片内容，不允许为了铺满而裁切掉核心动作
- 主图外围空白区不直接留白，而是使用当前图片自身生成的毛玻璃高斯模糊背景进行填充，确保视觉上铺满展示区，同时不丢失关键信息
- 图片区域应明显大于任何文字或表单区
- 当前步骤说明文字压在图片底部，做半透明说明条
- 在主舞台区域内预留未来多媒体控件位置，避免后续扩展语音提示或音效能力时重做主布局

说明条要求：

- 位于图片底部叠层
- 半透明深/浅底皆可，但必须保证文字可读
- 展示当前步骤核心说明文案
- 不在图片外再单独占一整块说明卡区域
- 最大高度不得超过图片显示区高度的 `1/3`
- 当说明文案超出说明条最大高度时，只允许说明条内部滚动，不允许把图片区整体顶高

如果当前步骤没有图片资源：

- 仍保留相同尺寸的主舞台区域
- 使用占位背景和缺图提示
- 占位态仍需沿用“主舞台 + 说明条”的结构
- 不允许因为缺图而把页面退化回“文字为主”的纵向布局

多媒体控制位要求：

- 在左侧主舞台区域内预留一组紧凑的媒体控制位
- 默认位置为主图内部右上角覆盖层，避免挤占主图下方导航高度
- 未来用于承载：
  - 音频播放
  - 重播
  - 静音
- 控件区应作为独立的小型悬浮操作组存在，不与步骤说明条混排
- 即使当前版本未启用音频素材，也必须预留稳定的对齐位置，避免后续扩展时打破当前布局比例

#### 4.2.3 步骤导航区

步骤导航放在左侧图片下方，不放在右栏。

导航形式固定为：

- 序号
- 短标题

明确不采用：

- 缩略图条
- 纯图标点位

导航要求：

- 可以看出总步骤和当前所在步骤
- 当前步骤状态必须高亮
- 单个项保持短文本，避免撑高
- 视觉上是辅助导航，不与主图争抢注意力

针对步骤数较多的场景（例如 15-20 步），导航区溢出规则强制如下：

- 导航区只允许单行横向排布
- 导航区自身支持横向手势滑动，即 `overflow-x: auto`
- 横向滚动条默认隐藏，但仍保留可滑动能力
- 当前步骤切换后，导航区必须自动滚动到让当前步骤尽量处于可视区域居中位置

明确不允许：

- 导航项换行后撑高左栏
- 为容纳更多步骤而压缩主图高度
- 把长步骤导航移入右栏占用记录区空间

## 5. 右侧固定记录栏

右侧固定记录栏必须在一个屏幕内完整常驻展示以下内容：

1. 返回学生选择
2. 统计数字概览
3. 完成等级
4. 错误等级
5. 教师备注
6. 上一步 / 中断保存 / 下一步（或完成训练）

右栏不允许整体滚动。

本页的主要使用场景明确为：

- 平板设备
- 大尺寸触摸显示屏

因此右栏除了满足“信息常驻”，还必须满足触控友好和明确的物理操作感。

### 5.0 右栏通用交互与视觉语言

右栏所有可点击项包括：

- 返回学生选择
- 完成等级单选项
- 错误等级单选项
- 底部动作按钮

这些点击项必须满足以下底线规则：

- 最小触控高度不得低于 `44px`
- 优先按 `48px` 触控高度设计
- 不允许为了压缩高度而牺牲点击准确率

如果右栏空间不足，优先处理顺序必须是：

1. 微调左右栏宽度比例
2. 优化文案长度、换行策略和标签排版
3. 压缩非交互装饰间距

明确不允许：

- 将触控目标压缩到 `44px` 以下
- 通过缩小点击面来交换“整页无滚动”

右栏视觉风格要求统一为带厚度感的扁平操作面板语言：

- 各项操作卡片采用类似“磁吸贴”或“木质积木”的块面风格
- 视觉上强调轻微立体感、可按压感和清晰边界
- 右栏整体应像一个物理操作面板，而不是普通表单列表

这一风格要求至少覆盖：

- 统计概览卡片
- 完成等级与错误等级的可点击选项
- 返回按钮
- 底部动作按钮

必须实现对应的物理交互反馈，不允许只有静态外观：

- `Active`（按下）状态：
  - 组件视觉厚度减少
  - 组件产生明确的 Y 轴下沉效果
  - 阴影收短或减弱，形成“被按下去”的段落感
- `Selected`（选中）状态：
  - 组件应具备稳定可持续的选中表现
  - 通过颜色、描边、厚度层级或高光变化明确区分于未选中状态
  - 选中态不能只依赖文字变化，必须有块面级别的视觉确认

目标是让触屏点击时同时具备：

- 按下确认感
- 选中确认感
- 可恢复到默认态的物理一致性

### 5.1 返回学生选择

- 放在右栏最顶部
- 作为小型次级按钮
- 不放到底部动作区

### 5.2 统计数字概览

只保留数字概览，不保留逐步状态列表。

必须常驻展示：

- 已记录步骤
- 独立完成
- 口头提示
- 协助完成
- 未完成

这些统计应为紧凑卡片或紧凑数字块，优先保证一扫就能读到结果。

### 5.3 完成等级

完成等级必须常驻可见。

保留现有四类语义：

- 独立完成
- 口头提示
- 协助完成
- 未完成

交互可继续沿用按钮式单选，但视觉上需要压缩垂直占位，同时必须满足触控高度底线。

### 5.4 错误等级

错误等级必须常驻可见。

保留现有四类语义：

- 无
- 轻度
- 中度
- 重度

同样优先采用紧凑单选方式，同时必须满足触控高度底线。

### 5.5 教师备注

教师备注必须常驻可见，且采用固定高度策略：

- 备注框显示高度固定为 3 行可见高度
- 输入内容超出后，仅备注框内部滚动
- 不允许备注区把整个页面顶高

教师备注区是右栏高度控制中的关键约束，必须优先服从“整页无滚动”目标。

针对平板和触摸大屏的系统虚拟键盘，还必须增加防遮挡策略：

- 当教师备注输入框获得焦点并弹起系统软键盘时，页面进入临时“键盘避让模式”
- 键盘避让模式下，允许右侧区域为了避让键盘而临时进行平滑上移或局部纵向调整
- 该调整只服务于键盘防遮挡，不等同于恢复普通页面滚动
- 必须保证键盘弹起时，教师备注输入框与底部关键动作区至少仍有可操作路径
- 不能出现“下一步 / 中断保存”被软键盘完全遮挡且无法触达的情况

实现策略可采用以下一种或组合：

- 基于 `visualViewport` 或等价视口能力动态收缩可用高度
- 基于 Electron 客户端能力或宿主能力在软键盘弹起时调整页面可视区
- 通过 CSS 环境变量、安全区变量或运行时变量重算右栏底部可见范围
- 在输入框聚焦时，让右栏进入临时的键盘安全布局

兜底行为要求：

- 如果软键盘存在时无法同时保证备注输入与底部动作可达，则底部动作点击前必须先触发输入框失焦并收起键盘
- 在键盘收起前，不允许直接把关键动作留在完全不可见的遮挡区内

### 5.6 底部动作区

底部动作区必须常驻展示：

- 上一步
- 中断保存
- 下一步 / 完成训练

要求：

- 三个动作固定在右栏底部区域
- 不随着备注内容增长而下沉到屏幕外
- 主动作突出，次动作弱化，但三者都必须在同一屏内可达
- 按钮本体和点击面同样满足最小 `44px`、优先 `48px` 的触控高度要求

## 6. 滚动规则

本设计的滚动策略是强约束：

- 页面整体：不滚动
- 左右两栏：不滚动
- 右栏整体：不滚动
- 教师备注输入框：允许内部滚动
- 图片底部说明条：在超长文本场景下允许内部滚动

补充说明：

- 触屏设备上软键盘弹起时，允许进入临时键盘避让模式
- 键盘避让模式下的局部上移、局部滚动或视口重算，不视为违背“整页无滚动”的桌面布局规则
- 键盘收起后，页面必须恢复到标准无滚动静态布局

同时必须满足触控底线规则：

- 右栏所有可点击项的最小触控高度不得低于 `44px`
- 优先维持 `48px` 级别的可点区域
- 不允许通过压缩点击面来交换无滚动布局

如果实现后发现内容超出视口，优先处理方式必须是：

1. 调整左右栏比例，优先给右栏释放可用宽度和高度
2. 优化文案长度、标题换行和卡片内部排版
3. 压缩非交互间距与装饰性留白
4. 压缩统计模块和上下文模块的展示密度，但不得压缩触控目标到 `44px` 以下

不允许直接通过给页面加纵向滚动解决问题。

## 7. 信息层级

页面层级优先级从高到低如下：

1. 当前步骤图片
2. 图片上的步骤说明条
3. 右栏记录动作
4. 左下步骤导航
5. 统计数字概览
6. 任务/学生上下文说明

这意味着：

- 图片必须是最大视觉块
- 说明文案不应抢过图片
- 统计概览不能大到压缩记录区
- 任务/学生信息应压缩为上下文标签，而不是页面头部主角

## 8. 当前代码对应改造点

本次布局改造预期主要落在：

- `src/views/self-care/TaskExecution.vue`

需要调整的现有结构：

- 移除当前独立 `header` 作为主布局顶部区块
- 将 `task-execution-stage` 与 `task-execution-footer` 合并为单一双栏结构
- 将现有执行概览从下方区域并入右侧固定工作栏
- 将当前步骤说明和媒体标签区重构为图片主舞台
- 新增左下步骤导航区

本次不应扩散到：

- 路由定义
- 训练记录 API
- 任务数据合同
- 其他 self-care 页面

## 9. 非目标

本次明确不做：

- 改动训练记录业务语义
- 增删记录字段
- 引入新的执行流程步骤
- 增加逐步状态列表
- 增加全屏弹层、抽屉、二级页
- 为了适配内容而恢复页面滚动
- 扩展到移动端视觉精修

移动端只要求结构不崩，不是本次主设计目标。

## 10. 验收标准

当实现完成后，应满足以下验收项：

1. 桌面全屏状态下，页面不出现整体上下滚动条。
2. 左侧当前步骤图明显占据主版面。
3. 当前步骤说明以图片底部半透明说明条呈现。
4. 步骤导航位于左侧图片下方，形式为“序号 + 短标题”。
5. 右栏固定展示返回按钮、统计数字概览、完成等级、错误等级、教师备注、上下步动作。
6. 教师备注区固定 3 行可见高度，长内容只在输入框内部滚动。
7. 执行概览不再占据页面底部独立整块区域。
8. 页面结构不依赖扩展折叠或弹窗才能完成核心记录操作。
9. 当前步骤主图完整保留，不因铺满布局而裁切核心动作。
10. 主图外围空白区使用主图毛玻璃高斯模糊背景填充，而不是直接留白。
11. 图片底部说明条最大高度不超过图片高度的 `1/3`，长文案只在说明条内部滚动。
12. 右栏所有可点击项满足最小 `44px`、优先 `48px` 的触控高度要求。

## 11. 风险与实现提醒

实现阶段需要重点注意：

- `imagePath` 缺失时的占位态不能破坏主舞台尺寸
- 当前中英文或长任务名场景可能挤占左侧上方上下文区，需做溢出控制
- 步骤导航短标题必须截断或限宽，避免一长串标题挤爆左栏底部
- 说明条在超长文本场景下必须独立滚动，不能反向挤压主图显示高度
- 该项目在本页实现中应直接使用原生 CSS 进行布局和样式开发，不以组件库默认布局能力作为约束边界
- 开发阶段应使用 CSS Grid / Flex 与原生 CSS 变量直接控制左右栏比例、控件高度、说明条高度和区块间距
- 触控目标尺寸与无滚动目标发生冲突时，优先调整布局比例与文案排版，而不是缩小点击区域

## 12. 结论

本页正式采用“左侧图片主舞台 + 右侧固定记录栏”的桌面执行页结构。

核心判断标准只有两个：

- 孩子的注意力是否首先落在当前步骤图上
- 老师是否能在不滚动页面的前提下完成完整记录

如果某个实现细节同时破坏了这两点中的任意一点，就应视为偏离本规格。
